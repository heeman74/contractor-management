  <action>
    1. **router.py**: Create `router = APIRouter(tags=["chat"])` with:

    **WebSocket endpoint** — `@router.websocket("/ws/chat/{thread_id}")`:
    - Accept `token: str = Query(...)` — JWT in query param (browser WS API cannot send headers)
    - Validate JWT with `decode_token(token)` BEFORE `websocket.accept()`. Close with code=4401 if invalid.
    - Extract user_id and company_id from JWT claims
    - Verify user is member of thread via ChatService (get membership, reject if not member with 4403)
    - Set RLS context using `SET LOCAL` (same as existing tenant.py pattern) for any DB operations
    - `await manager.connect(websocket, thread_id, user_id)`
    - Start Redis relay as background task: `relay = asyncio.create_task(manager.relay_from_redis(thread_id))`
    - Message loop with re-validation every 5 minutes (STATE.md decision: "WebSocket JWT re-validated server-side every 5 minutes; close with 4401 on expiry"):
      ```python
      last_validated = asyncio.get_event_loop().time()
      while True:
          now = asyncio.get_event_loop().time()
          if now - last_validated > 300:
              try:
                  decode_token(token)
                  last_validated = now
              except Exception:
                  await websocket.close(code=4401)
                  break
          data = await asyncio.wait_for(websocket.receive_json(), timeout=30.0)
          # handle message types
      ```
    - Handle incoming message types:
      - `{"type": "message", ...}` — call ChatService.send_message, broadcast via manager, fire FCM for offline recipients
      - `{"type": "typing"}` — broadcast `{"type": "typing", "user_id": user_id, "user_name": sender_name}` to thread
      - `{"type": "read", "seq": N}` — call ChatService.mark_read, broadcast read receipt update
      - `{"type": "ping"}` — respond with `{"type": "pong"}`
    - finally block: `manager.disconnect(websocket, thread_id, user_id)` and `relay.cancel()`
    - For the "message" type: after saving to DB, determine offline recipients (thread members not in manager._connections[thread_id]), call NotificationService.send_chat_notification for them

    **REST endpoints** (all require `Depends(get_current_user)`):
    - `GET /chat/threads?project_id={id}` — list threads for user on project. Returns list[ChatThreadResponse].
    - `GET /chat/threads/{thread_id}/messages?before_seq={seq}&limit=50` — cursor-paginated messages. Returns list[ChatMessageResponse]. Also accepts `since_seq` param for reconnect catch-up.
    - `POST /chat/threads/{thread_id}/messages` — REST send message (fallback for offline sync drain). Body: SendMessageRequest. Returns ChatMessageResponse with server-assigned seq.
    - `POST /chat/threads/{thread_id}/read` — mark read. Body: MarkReadRequest.
    - `GET /chat/threads/{thread_id}/receipts` — get read receipts for thread. Returns list[ChatReadReceiptResponse].
    - `POST /chat/messages/{message_id}/attachment` — file upload for chat. Accept UploadFile. Save via aiofiles to `uploads/chat/{message_id}/{filename}`. Update message attachment_url. Return updated ChatMessageResponse.
    - `PUT /chat/threads/{thread_id}/mute` — toggle mute. Body: `{"muted": true/false}`.
    - `POST /chat/threads` — create thread (for auto-creation hook). Body: project_id, thread_type, trade_scope_id (optional), name, member_ids. Returns ChatThreadResponse.

    ```python
    async def send_chat_notification(

        recipient_user_ids: list[uuid.UUID],
        mention_all: bool, mentioned_user_ids: list[uuid.UUID],
        muted_user_ids: list[uuid.UUID],
    ) -> None:
    ```
    - Build FCM body per D-14: `"{sender_name} ({trade_scope_name}): {message_preview[:100]}"`
    - For each recipient: skip if muted AND not mentioned; send FCM with data payload `{"type": "chat_message", "thread_id": str(thread_id)}`
    - Use existing `_send_to_token` method for actual FCM dispatch
    - Fire-and-forget pattern (don't block on FCM errors)
