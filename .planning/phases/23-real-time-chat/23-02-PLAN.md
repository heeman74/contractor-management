    1. **chat_dao.dart**: DAO extending DatabaseAccessor with methods:
    - `watchThreadsByProject(String projectId)` — Stream<List<ChatThread>> ordered by lastMessageAt desc, filtered by deletedAt.isNull()
    - `watchMessages(String threadId)` — Stream<List<ChatMessage>> ordered by seq ASC, filtered by deletedAt.isNull()
    - `insertMessage(ChatMessagesCompanion msg)` — insertOnConflictUpdate
    - `upsertThread(ChatThreadsCompanion thread)` — insertOnConflictUpdate
    - `upsertReadReceipt(ChatReadReceiptsCompanion receipt)` — insertOnConflictUpdate
    - `updateMessageStatus(String id, String status)` — update status field (pending -> sent -> failed)
    - `trimMessages(String threadId, {int keep = 100})` — delete messages where seq < (max_seq - keep) for this thread. Keeps local cache at 100 per thread (D-13).
    - `getLastSeq(String threadId)` — returns max seq for thread (for cursor pagination)
    - `markThreadRead(String threadId, int unreadCount)` — update unreadCount on thread
    - `batchInsertMessages(List<ChatMessagesCompanion> messages)` — batch insert for sync catch-up
    - Import: `import 'package:drift/drift.dart' hide isNotNull, isNull;` (MEMORY.md pattern)

    2. **chat_ws_client.dart**: WebSocket client using `web_socket_channel`:
    - Constructor: `ChatWsClient({required String baseWsUrl, required Future<String> Function() tokenProvider})`
    - `connect(String threadId)` — IOWebSocketChannel.connect to `$baseWsUrl/ws/chat/$threadId?token=$token`
    - Exponential backoff reconnect: 1s -> 2s -> 4s -> 8s -> 16s -> 32s -> 64s cap. Reset on successful connect.
    - `Stream<Map<String, dynamic>> get messages` — broadcast stream controller
    - `send(Map<String, dynamic> payload)` — send JSON over WS
    - `sendTyping()` — send `{"type": "typing"}` event
    - `sendRead(int seq)` — send `{"type": "read", "seq": seq}` event
    - Heartbeat: send `{"type": "ping"}` every 30 seconds. If no response in 10s, reconnect.
    - `dispose()` — cancel subscription, close channel and controller
    - Handle incoming message types: 'message', 'typing', 'read_receipt', 'pong'
    - On reconnect: emit a 'reconnected' event so consumers know to fetch missed messages

    3. **chat_sync_service.dart**: Offline message queue drain:
    - Uses SyncQueue pattern: reads pending entries where `entityType == 'chat_message'`
    - On connectivity restore (listen to connectivity changes): drain pending messages via ChatWsClient.send() in FIFO order
    - On successful server ACK (message echoed back with seq): update SyncQueue entry status to 'synced', update ChatMessage status from 'pending' to 'sent', set seq from server response
    - On failure: increment retryCount, mark 'failed' after 3 retries
    - `queueOfflineMessage(ChatMessagesCompanion msg)` — writes to SyncQueue with entityType 'chat_message' and payload as JSON-encoded message data

    4. **chat_repository.dart**: Bridges API + DAO:
    - `fetchThreads(String projectId)` — GET /chat/threads?project_id={id} via Dio, upsert results into Drift
    - `fetchMessages(String threadId, {int? beforeSeq, int limit = 50})` — GET /chat/threads/{id}/messages?before_seq={seq}&limit={limit}, insert into Drift
    - `fetchMissedMessages(String threadId, int sinceSeq)` — GET /chat/threads/{id}/messages?since_seq={seq}, insert into Drift (for reconnect sync)
    - `uploadAttachment(String messageId, File file, String type)` — POST /chat/messages/{id}/attachment (multipart)
    - `sendReadReceipt(String threadId, int seq)` — POST /chat/threads/{id}/read (REST fallback)
    - Uses Dio from GetIt service locator (same pattern as existing repositories)

    5. **chat_providers.dart**: Riverpod providers:
    - `chatDaoProvider` — Provider that reads AppDatabase from GetIt and returns ChatDao
    - `chatThreadsProvider` — StreamProvider.autoDispose.family<List<ChatThread>, String> watching Drift threads by projectId
    - `chatMessagesProvider` — StreamProvider.autoDispose.family<List<ChatMessage>, String> watching Drift messages by threadId
    - `chatWsClientProvider` — Provider.autoDispose.family<ChatWsClient, String> creating WS client per threadId with token from auth
    - `chatRepositoryProvider` — Provider that creates ChatRepository with Dio from GetIt
    - `chatSyncServiceProvider` — Provider that creates ChatSyncService
