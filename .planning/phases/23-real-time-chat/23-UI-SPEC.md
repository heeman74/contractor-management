## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Avatar border gap, read receipt icon gap, typing indicator dot gap, mention badge padding |
| sm | 8px | Message bubble internal padding (compact), thread list item vertical padding, attachment preview gap |
| md | 16px | Default message bubble padding, chat input area padding, thread list side margins, thread header padding |
| lg | 24px | Thread list section header margin, attachment preview max height padding, thread name + member count gap |
| xl | 32px | Layout gap between thread panel and message panel (web sidebar split) |
| 2xl | 48px | Major section breaks (project header to thread list) |
| 3xl | 64px | Page-level bottom padding (clears bottom navigation bar + safe area on mobile) |

Exceptions:
- Message input text field: minimum 48px height (touch target on mobile; provides comfortable typing area)
- Send button: minimum 48px x 48px touch target on mobile
- Attachment action buttons (photo, PDF): minimum 48px touch target
- Thread list row: minimum 56px height (avatar + two lines of text needs room; standard list tile minimum)
- Avatar size: 32px (diameter) on message bubbles — not on spacing scale, fixed visual size

## Color

### Web (shadcn CSS variables — base-nova, neutral, light mode)

| Role | CSS Variable | Approximate Value | Usage |
|------|-------------|-------------------|-------|
| Dominant (60%) | `--background` | `oklch(1 0 0)` — white | Chat screen background, message list background, thread list background |
| Secondary (30%) | `--card` / `--muted` | `oklch(1 0 0)` / `oklch(0.97 0 0)` — near-white / light gray | Incoming message bubbles (other party), thread list hover state, read receipt row background, typing indicator bubble |
| Accent (10%) | `--primary` | `oklch(0.205 0 0)` — near-black | Outgoing message bubbles (own messages), Send button fill, @mention chips, unread message count badge, active thread highlight in thread list |
| Destructive | `--destructive` | `oklch(0.577 0.245 27.325)` — red | Delete message (if implemented) confirmation dialogs only |

Accent reserved for:
1. Outgoing message bubbles (own messages — visually distinguished from incoming)
2. Send button fill (primary action in message input area)
3. Unread message count badge on thread list row
4. Active/selected thread highlight in thread list
5. @mention chips in message input field (auto-complete selections)

### Mobile (Material 3 ColorScheme.fromSeed — seed `#1E4D8C`)

| Role | M3 Token | Usage |
|------|----------|-------|
| Dominant (60%) | `colorScheme.background` | Scaffold background, message list area, thread list screen |
| Secondary (30%) | `colorScheme.surface` / `colorScheme.surfaceVariant` | Incoming message bubbles, thread list tile background, typing indicator bubble, read receipt row |
| Accent (10%) | `colorScheme.primary` | Outgoing message bubbles, Send IconButton, unread badge fill, active thread tile highlight, @mention chip background |
| Destructive | `colorScheme.error` | Delete message confirmation dialogs only |

### Message Bubble Distinction

Outgoing (own) messages use accent (`colorScheme.primary` / `--primary`) background with `onPrimary` text color. Incoming (other) messages use secondary surface (`colorScheme.surfaceVariant` / `--muted`) background with default foreground text color. This is the universal chat convention — no deviation.

### Thread Type Indicators

Thread list rows show a small type chip or icon to distinguish thread types:
- Trade scope thread: show trade color dot (same chart-color rotation from Phase 22 TradeProgressCard palette — `--chart-1` through `--chart-5` cycling)
- Project-wide thread: show a group icon (`Users` from lucide / `Icons.groups` on mobile) in `colorScheme.secondary`

## Interaction Contracts

### Chat Screen — Thread List (Mobile)

- Accessible from bottom navigation tab (new "Messages" tab, or from `ProjectDetailScreen` → "Chat" button per project).
- Two sections rendered as `SliverList` groups: "Trade Conversations" (scope threads for this project) and "Project Group" (project-wide thread).
- Each thread row shows: thread type indicator (trade color dot or group icon), thread name (Heading), last message preview (Label, 1 line truncated with ellipsis), timestamp (Label, right-aligned, relative format), unread badge (accent fill, Label text).
- Unread badge hidden when all messages read. Shown as integer count (e.g. "3") or "99+" for high counts.
- Tap thread row → `context.push(RouteNames.chatThread(threadId))`.
- Thread list sorted: unread threads first (by unread count desc), then by last message timestamp desc.
- Trade scope threads auto-appear when contractor is assigned to that scope (D-04). No manual group creation.
- Long-press on thread row → `showModalBottomSheet` with options: "Mute Conversation" / "Unmute Conversation".

### Chat Thread Screen (Mobile)

- AppBar: thread name (Heading) + member count for project-wide threads (Label, e.g. "5 members").
- Back button: returns to thread list.
- Body: `ListView.builder` with `reverse: true` (newest at bottom, natural chat scroll). Drift `watchMessages(threadId)` stream drives the list.
- Date separators: `SliverToBoxAdapter` divider with centered date chip ("Today", "Yesterday", "Mar 18") between messages from different days.
- Scroll-to-top triggers paginate older messages: `ScrollController` `atEdge && position.pixels == 0` → fetch `GET /chat/threads/{id}/messages?before_seq={firstSeq}&limit=50`. Shows "Load older messages" loading spinner at top while fetching.
- Typing indicator: shown as last item in list when WebSocket typing event received from other party. Auto-hides after 3 seconds.
- Read receipts: shown below own outgoing messages. Single check icon = message sent to server. Double check icon (or small avatar circles) = all thread members have read.
- On screen enter: send `{type: "read", seq: lastVisibleSeq}` WebSocket event. Server upserts `chat_read_receipts`.
- `ChatInputBar` always visible above keyboard. `resizeToAvoidBottomInset: true` on `Scaffold`.

### Message Input (Mobile)

- `TextField` multiline, `minLines: 1`, `maxLines: 5`. Grows up to 5 lines then scrolls.
- Send button: `IconButton` with `Icons.send`. Enabled (accent color) only when input non-empty OR attachment staged. Tap sends immediately: writes to Drift + sync queue (D-12).
- Offline behavior: if `connectivityProvider` shows offline, write message to SyncQueue `entityType: 'chat_message'`. Show clock icon on bubble. Drain queue via WebSocket when connectivity restores (D-12).
- Attachment button: `Icons.attach_file`. Opens `ChatAttachmentPicker` bottom sheet.
- @mention: typing "@" shows autocomplete suggestion overlay above input. Shows thread members as `ListTile` rows (avatar + name). Tap inserts `@{name}` text and tags user_id in `mentions` list. Typing "@all" inserts `@all` chip and sets `mention_all: true`.
- @mention chip visual: small `Chip` widget with accent fill inserted inline in text field. Uses `ReplacementEditingController` pattern or `RichTextField` equivalent.

### Message Bubble Interactions (Mobile)

- Tap photo thumbnail → full-screen `PhotoView` (same pattern as Phase 22 task photo viewer).
- Long-press own message → bottom sheet: "Copy Text" | (future: "Delete Message"). No edit.
- Long-press incoming message → bottom sheet: "Copy Text". No delete.
- Tap PDF tile → `url_launcher` opens PDF in system viewer (same as Phase 22 task attachments).
- Tap read receipt row → `showModalBottomSheet` with full list of readers + timestamps.
- Tap "Annotated photo" chip on shared annotated photo → opens photo with annotation overlay rendered (reuse Phase 22 `PhotoAnnotationScreen` in view-only mode: `readOnly: true`).

### File Sharing (Mobile)

- Photo: `ImagePicker` (camera or gallery). After selection, show staging preview above input field with remove button. On send, upload via `POST /chat/messages/{messageId}/attachment` then send message with `attachmentId`.
- PDF: `FilePicker` (PDF only). Same staging + upload pattern as photo.
- Annotated photo: shows sheet listing task photos that have `annotationData != null`. User selects one. Message sent with `attachmentType: 'annotated_photo'` and `annotationData` payload. No re-upload needed — references existing attachment.
- Upload in-progress: bubble shows "Uploading..." label. On success, replaces with file preview. On failure: shows "Failed to upload. Tap to retry." — tap retriggers upload.

### Web Chat Panel Interactions

- Thread list panel (left): click thread row → loads MessageList on right. Active thread highlighted with `bg-muted`.
- MessageList scroll: `ScrollArea` with `overflowY: auto`. On initial load, scroll to bottom. Scroll up → shows older messages (fetch on `IntersectionObserver` at top sentinel).
- @mention autocomplete: `Popover` anchored above input. Filters thread members as user types after "@". Press `Enter` or click to select. Escape closes without inserting.
- Typing indicator: debounce 500ms on keydown emits `{type: "typing"}` over WebSocket. Other party sees TypingIndicator component (animated dots + "name is typing..." text) at bottom of their MessageList.
- WebSocket connection state: connection status indicator in thread header — no indicator when connected (clean UX), yellow dot when reconnecting, hidden when connected.

## States and Transitions

### Thread List Row States

| State | Visual |
|-------|--------|
| `unread` | Unread badge (accent fill + count), thread name at weight 600, last message preview at weight 400 normal |
| `read` | No badge, thread name at weight 400, last message preview at weight 400 muted |
| `muted` | Bell-slash icon appended to thread name, unread badge hidden |
| `active` (web only) | `bg-muted` background on row |

### Message Bubble States

| State | Visual |
|-------|--------|
| `sending` (outbox) | Clock icon on bubble bottom-right; bubble opacity 0.7 |
| `sent` | Single check icon (own messages); full opacity |
| `read` | Double check icon or small avatar circles of readers (own messages) |
| `failed` | Red border on bubble; "Failed to upload. Tap to retry." text below |

| State | Visual |
|-------|--------|
| `connected` | No indicator — clean UX |

| State | Visual |

| `active` | Animated 3-dot bubble at list bottom + "{First Name} is typing..." Label text. Auto-hides after 3s. |

## Accessibility

- Thread list tiles: `Semantics(label: "{Thread name}, {N} unread messages, last message: {preview text}")` wrapping each tile
- Unread badge: `Semantics(label: "{N} unread messages")` on badge widget
- Send button: `Semantics(label: "Send message", button: true, enabled: isEnabled)`
- Attachment button: `Semantics(label: "Add attachment", button: true)`
- Message bubbles: `Semantics(label: "{Sender name}: {message content}, {timestamp}", liveRegion: true)` on incoming messages (live region announces new incoming messages)
- Typing indicator: `Semantics(label: "{First Name} is typing", liveRegion: true)` — announces to screen reader
- Photo thumbnails in chat: `Semantics(label: "Shared photo from {Sender name}{annotation_suffix}", image: true)` where annotation_suffix = ", annotated" when annotationData present
- PDF attachment tiles: `Semantics(label: "PDF: {filename}", button: true)`
- Read receipt row: `Semantics(label: "Read by {names}")` wrapping the row
- All interactive elements: minimum 48px touch target on mobile
- Message input `TextField`: `textInputAction: TextInputAction.newline` (multiline) — Send via button tap, not Enter key (field workers often use Enter for line breaks)
- Web: `MessageList` has `role="log"` and `aria-live="polite"` on the container; each message has `aria-label` with sender + content
- Web input: `<textarea aria-label="Message {threadName}">`, send button `aria-label="Send message"`, attachment button `aria-label="Add attachment"`
- Color never sole differentiator: outgoing vs incoming messages distinguished by both alignment (left/right) AND background color, plus "You" vs sender name label
- @mention chips: `Semantics(label: "@{name} mentioned", chip: true)` with delete semantics for removal
