**Create `project_providers.dart`** with Riverpod providers:

1. `projectDaoProvider` — Provider that gets ProjectDao from GetIt (or ref.watch appDatabase)
2. `tradeScopeDaoProvider` — Provider for TradeScopeDao
3. `taskDaoProvider` — Provider for TaskDao
4. `projectListProvider` — StreamProvider that watches `projectDao.watchProjectsByCompany(companyId)` using auth state for companyId. For contractor role, filter to projects where user has an assigned scope (requires a DAO method or post-filter).
5. `tradeScopesProvider(String projectId)` — StreamProvider.family that watches `tradeScopeDao.watchScopesByProject(projectId)`
6. `tasksProvider(String tradeScopeId)` — StreamProvider.family that watches `taskDao.watchTasksByScope(tradeScopeId)`

**Create `project_status_badge.dart`:**
A small stateless widget that maps project status strings to colors:
- draft: grey background, grey text
- planning: blue background, blue text
- active: green background, green text
- on_hold: yellow/amber background, amber text
- complete: teal background, teal text
- archived: grey background, grey-400 text

Same pattern for trade scope and task statuses. Use a single `StatusBadge` widget with a `statusColorMap` parameter or use the existing badge pattern from the jobs feature.

**Create `trade_scope_card.dart`:**
A Card widget per UI-SPEC:
- Left side: 12px Container with trade color as background (circle or square), trade name in semibold
- Below name: contractor name or "Unassigned" in muted text
- Right side: "3/8 tasks" count, status badge
- Bottom: 4px LinearProgressIndicator with trade color, grey-100 track, value = completedTasks/totalTasks
- Card onTap callback for navigation
- Props: tradeName (String), tradeColor (Color), contractorName (String?), completedTasks (int), totalTasks (int), status (String), onTap (VoidCallback)
