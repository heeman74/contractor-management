  <action>
All Route Handlers use `FASTAPI_URL` env var (default `http://localhost:8000`). Add `FASTAPI_URL` to `web/.env.local`.

**Login Route Handler** (`web/src/app/api/auth/login/route.ts`):
1. Export async `POST` function accepting `NextRequest`
2. Read JSON body (email + password)
3. `fetch` to `${FASTAPI_URL}/api/v1/auth/login` with JSON body
4. If FastAPI returns non-200, forward the error response (status + body) to client
5. On success, parse `TokenResponse` from FastAPI
6. Use `await cookies()` (MUST await — Next.js 16 async cookies) to set:
   - `access_token`: httpOnly, secure (in prod), sameSite "lax", path "/", maxAge 900 (15 min)
   - `refresh_token`: httpOnly, secure (in prod), sameSite "lax", path "/api/auth/refresh", maxAge 2592000 (30 days)
7. Return JSON with `{ user_id, company_id, roles }` only — NEVER return tokens to client

**Refresh Route Handler** (`web/src/app/api/auth/refresh/route.ts`):
1. Export async `POST` function
2. Read `refresh_token` from cookies via `await cookies()`
3. If no refresh_token cookie, return 401
4. `fetch` to `${FASTAPI_URL}/api/v1/auth/refresh` with `{ refresh_token }` body
5. If FastAPI returns non-200, clear both cookies and return 401
6. On success, set new access_token and refresh_token cookies (same options as login)
7. Return 200 with `{ user_id, company_id, roles }`

**Logout Route Handler** (`web/src/app/api/auth/logout/route.ts`):
1. Export async `POST` function
2. Read `access_token` from cookies
3. If present, call `${FASTAPI_URL}/api/v1/auth/logout` with `Authorization: Bearer ${access_token}`
4. Always clear both cookies (access_token path "/" and refresh_token path "/api/auth/refresh") by setting maxAge 0
5. Return 200

**API Proxy** (`web/src/app/api/proxy/route.ts`):
1. Export `GET`, `POST`, `PATCH`, `DELETE` functions — all delegate to a shared `handleProxy` function
2. `handleProxy` reads `path` from URL search params (e.g., `/api/proxy?path=/api/v1/jobs`)
3. Reads `access_token` from cookies
4. Forwards request to `${FASTAPI_URL}${path}` with `Authorization: Bearer ${access_token}` header
5. Forwards the original request body (if POST/PATCH) and content-type
6. Returns FastAPI's response (status + body) to client
7. If no access_token cookie present, return 401

IMPORTANT: All `cookies()` calls MUST use `await` (Next.js 16 requirement). Missing `await` is a silent bug.

**apiClient** (`web/src/lib/api-client.ts`):
1. Export `ApiError` class extending Error with `status: number` and `detail: string`
2. Export `apiClient<T>(path: string, init?: RequestInit, retry?: boolean): Promise<T>`:
   - Calls `/api/proxy?path=${encodeURIComponent(path)}` (routes through the proxy Route Handler)
   - Passes through method, body, headers from `init`
   - On 401 and `retry !== false`:
     - Call `POST /api/auth/refresh` (the refresh Route Handler)
     - If refresh succeeds: retry original request with `retry=false`
     - If refresh fails: `window.location.href = "/login?reason=session_expired"` and throw
   - On non-200 (not 401): parse error body, throw `ApiError(status, detail)`
   - On success: return `resp.json() as Promise<T>`
3. Export convenience methods: `apiGet<T>(path)`, `apiPost<T>(path, body)`, `apiPatch<T>(path, body)`, `apiDelete<T>(path)`

**Server auth utility** (`web/src/lib/auth.ts`):
1. Mark as server-only: `import "server-only"` at top (or use Next.js convention)
2. Export `getServerUser(): Promise<AuthUser | null>`:
   - Read `access_token` from `await cookies()`
   - If no cookie, return null
   - Decode JWT using `jose.decodeJwt()` (decode only, no verification — FastAPI verifies on each request)
   - Extract `sub` (user_id), `company_id`, `roles` from payload
   - Return `{ user_id, company_id, roles }` or null if decode fails
3. This is used by Server Components to conditionally render based on user role

**proxy.ts** (`web/proxy.ts`):
1. Use Next.js 16 `proxy.ts` file (NOT `middleware.ts`)
2. Export default function `proxy(request: NextRequest)`:
   - Define PUBLIC_ROUTES: `["/login", "/api/auth/login", "/api/auth/refresh"]`
   - If pathname matches a public route or starts with `/_next/` or `/favicon.ico`, return `NextResponse.next()`
   - Check `request.cookies.has("access_token")`
   - If no cookie: redirect to `/login?redirectTo=${pathname}`
   - If has cookie: `NextResponse.next()`
3. Export `config.matcher`: `["/((?!_next/static|_next/image|favicon.ico).*)"]`
4. IMPORTANT: proxy.ts does NOT validate the token — it only checks cookie existence. This is an optimistic guard. Real validation happens when the Route Handler or Server Component calls the API.
