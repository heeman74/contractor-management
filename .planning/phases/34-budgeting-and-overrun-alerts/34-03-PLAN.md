<objective>
Turn budget state into alerts: evaluate a budget's spend against the 80%/100%
thresholds, claim each crossing exactly once, write the dashboard alert with the
locked copy, and push it by FCM to the users who actually hold `finance.view`.

Purpose: this is BUDG-03's engine. Every trigger added later (cost mutations,
budget edits, the nightly sweep, quote-revision deltas) calls into it, so
exactly-once firing and correct recipient targeting have to be right here, once.
Output: an atomic threshold claim, `BudgetService.evaluate_*`, a live-RBAC
recipient query, an FCM sender, and the two keystone tests.
</objective>

```python
@dataclass(frozen=True)
class BudgetAlertContext:
    """Everything the alert copy and the DashboardAlert row need about a budget's anchor."""
    project_id: uuid.UUID
    project_name: str
    trade_name: str | None     # None = project budget

_CLAIM_SQL: dict[BudgetThreshold, TextClause] = {...}

async def claim_threshold(self, budget_id: uuid.UUID, threshold: BudgetThreshold) -> bool
async def alert_context(self, budget: Budget) -> BudgetAlertContext | None
```

`_CLAIM_SQL` holds one `sqlalchemy.text(...)` statement per threshold, exactly:
```sql
UPDATE budgets SET warning_fired_at = now()
WHERE id = :budget_id AND warning_fired_at IS NULL AND deleted_at IS NULL
RETURNING id
```
(and the `overrun_fired_at` twin). `claim_threshold` executes the statement and
returns `result.scalar_one_or_none() is not None` — False means another
evaluator (a concurrent request or the nightly sweep) already claimed this
crossing, so the caller must NOT create an alert. This is the entire
exactly-once mechanism: no locks, no unique index, no unique-violation catching
(Phase 25 `mark_invoiced` precedent). Document that in the method docstring.
After a successful claim, call `self.db.expire(budget, ["warning_fired_at", "overrun_fired_at"])`
so the in-memory ORM object cannot serve a stale None to a later reader.

`alert_context` runs ONE query per budget:
- project budget → `select(Project.id, Project.name).where(Project.id == budget.project_id, Project.deleted_at.is_(None))`
- scope budget → `select(TradeScope.project_id, Project.name, TradeScope.trade_name)
  .join(Project, TradeScope.project_id == Project.id)
  .where(TradeScope.id == budget.trade_scope_id, TradeScope.deleted_at.is_(None))`
Returns `None` when the anchor row is gone/soft-deleted — callers then skip the
budget entirely (no alert can be written: `dashboard_alerts.project_id` is NOT NULL).
Column-only selects; never load whole ORM rows (relationships are lazy="raise").

Add the evaluation half to `BudgetService`:

```python
@dataclass(frozen=True)
class FiredBudgetAlert:
    """One threshold that just fired — the hand-off to notification dispatch."""
    alert_id: uuid.UUID
    alert_type: str
    company_id: uuid.UUID
    project_id: uuid.UUID
    trade_scope_id: uuid.UUID | None
    title: str
    body: str

_ALERT_TYPE_BY_THRESHOLD = {BudgetThreshold.warning: BUDGET_WARNING_ALERT_TYPE,
                            BudgetThreshold.overrun: BUDGET_OVERRUN_ALERT_TYPE}
_SEVERITY_BY_THRESHOLD = {BudgetThreshold.warning: "warning",
                          BudgetThreshold.overrun: "critical"}

async def evaluate_budget(self, budget: Budget, *, spent: Decimal | None = None) -> list[FiredBudgetAlert]
async def evaluate_for_project(self, project_id: uuid.UUID) -> list[FiredBudgetAlert]
async def evaluate_for_trade_scope(self, trade_scope_id: uuid.UUID) -> list[FiredBudgetAlert]
```

`evaluate_budget` reads top-down (stepdown rule), each step a named helper so the
method itself stays ~15 lines:
1. `spent` when not supplied ← `FinanceService(self.db).project_spend / trade_scope_spend`
   (never a new SUM).
2. `thresholds = crossed_thresholds(spent, budget.total)`; empty → return `[]` with
   no further queries.
3. `context = await self.repository.alert_context(budget)`; `None` → return `[]`.
   Resolve the context BEFORE claiming so a vanished anchor never burns a claim.
4. For each crossed threshold: `if not await self.repository.claim_threshold(budget.id, threshold): continue`
   then build `BudgetFacts(project_name=context.project_name, trade_name=context.trade_name, spent=spent, total=budget.total)`,
   `impact_text = budget_alert_text(facts, threshold)`, and persist a `DashboardAlert`
   with `company_id=budget.company_id`, `project_id=context.project_id`,
   `trade_scope_id=budget.trade_scope_id`, `severity=_SEVERITY_BY_THRESHOLD[threshold]`,
   `alert_type=_ALERT_TYPE_BY_THRESHOLD[threshold]`, `impact_text=impact_text`,
   `days_behind=None`, `remediation_text=None`, `affected_scope_ids=[]`,
   `is_read=False`, `rescheduling_payload=None`, `rescheduling_accepted=None`.
   Persist through `AlertRepository(self.db).create(alert)` if AlertRepository
   inherits the base create; otherwise `self.db.add(alert)` + `await self.db.flush()`
   exactly like `DashboardService._persist_alerts`. Collect a `FiredBudgetAlert`
   with `title=push_title_for(threshold)` and `body=impact_text` (UI-SPEC: the push
   body is byte-identical to impact_text).
5. Return the fired list. No `db.commit()` — the caller's transaction owns it, so
   a rollback un-claims the threshold too.

`evaluate_for_project` / `evaluate_for_trade_scope` resolve the active budget via
the repository (None → `[]`) and delegate. Push dispatch is added in Task 3 —
do not scatter notification logic into these methods.

**Concurrency test — use two independent sessions, never one.** The race this
guards is mutation-evaluation vs. the nightly cron: two SEPARATE transactions,
not two coroutines sharing a session. `asyncio.gather` over one `AsyncSession`
cannot reproduce it — SQLAlchemy async sessions forbid concurrent operations and
will either raise `InvalidRequestError` or serialize the calls, so the test would
pass without ever exercising the claim. Write it like this instead:

```python
async def _evaluate_in_own_session(company_id: uuid.UUID, budget_id: uuid.UUID) -> int:
    async with async_session_factory() as db:
        set_current_tenant_id(company_id)
        budget = await BudgetRepository(db).active_by_id_or_404(budget_id)
        fired = await BudgetService(db).evaluate_budget(budget)
        await db.commit()          # REQUIRED: without a commit the loser blocks
        return len(fired)          # on the row lock until the test times out
```
then `results = await asyncio.gather(_evaluate_in_own_session(...), _evaluate_in_own_session(...))`
and assert `sum(results) == 1`, that exactly ONE `dashboard_alerts` row exists for
that budget's warning type, and that `budgets.warning_fired_at` is non-null
exactly once (a single row, single timestamp). Commit the seeded budget and cost
entries before spawning the two sessions so both can see them. Patch
`send_budget_alert_notification` (Task 3) or run this test before push dispatch
exists, so the assertion is about alert rows only.
