# Phase 34 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** Phase 34 ships four UI deliverables, all extensions of shipped surfaces — no new pages, no new navigation:

1. **Budget summary section** (both platforms) — a `Budget / Spent / Remaining` row group appended inside the shipped `CostBreakdownSummary` between the Total row and the margin section, on the **project** and **trade-scope** variants only (budgets anchor project/scope — Phase 30 asymmetry; the job variant renders NO budget group).
2. **`SetBudgetDialog`** (web only, `finance.manage`-gated) — create/edit/remove a budget total, modeled on Phase 32's `RateHistoryDialog` conventions (D-13: web-edit + both-view).
3. **`AlertPanel` budget entries** (web only) — the two new alert types render through the existing severity path; one header copy fix. Mobile has NO alert surface (verified in 34-RESEARCH) — mobile's BUDG-03 channel is the FCM push.
4. **FCM push templates** — title/body locked here; body is byte-identical to the dashboard `impact_text`.

Everything inherits the "Job Ticket" design system unchanged from the Phase 30/32/33 contracts. This document pins layout, verbatim copy (test-asserted), and states for the budget surfaces only.

Pre-populated from: 34-CONTEXT.md (D-01..D-13 + specifics), 34-RESEARCH.md (Surfaces 1–5, state list), 33-UI-SPEC.md + 32-UI-SPEC.md (tokens, chip recipe, caption/figure conventions), direct reads of `CostBreakdownSummary.tsx`, `MarginSummarySection.tsx`, `FinanceFlagChip.tsx`, `ProjectCostsCard.tsx`, `AlertPanel.tsx`, `breakdown_row_widgets.dart` (2026-07-27). User input required: none — all contract questions were answered upstream.

## Color

Zero new hex values. One new sanctioned usage of the existing accent-chip recipe, one extension of the negative-numeral destructive sanction:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` `#f7f6f2` / `--foreground` `#0e1726` | Page background, body text (inherited) |
| Secondary (30%) | `--secondary`/`--muted` `#ece9e1`, `--card` `#ffffff` | Card surfaces, dialog surface, separators (inherited) |
| Accent (10%) | `--brand` `#f5a623` | Reserved list below — this phase adds exactly one usage: the **"Nearing budget" chip**, identical recipe to the shipped flag chips: `bg-brand/15` + `text-amber-900` (`#78350f`); mobile shared `FinanceFlagChip` (`Color(0x26F5A623)` container, `Color(0xFF78350F)` text) |
| Destructive | `--destructive` `#d64545` | Destructive actions ("Remove Budget" confirm button) + **new sanctioned semantic usage: negative Remaining numerals** (see below) |

Accent reserved for: checked permission toggles, active nav, focus rings, links, primary CTAs, the unrated-hours chip (Phase 32), the incomplete-data chip (Phase 33), and — new this phase — the **"Nearing budget" chip**. Nothing else.

**Negative Remaining treatment (locked):** when `remaining` is negative (over budget), the Remaining figure string (e.g. "-$1,200.00", sign before symbol via the shipped `formatMarginDollars` convention) renders in `text-destructive` on web and `Theme.of(context).colorScheme.error` on mobile — **numerals only**; the "Remaining" label and everything else never change color. This extends the Phase 33 negative-margin sanction (red = money lost) to its exact analog: a negative remaining IS money overspent. The minus sign carries the meaning; color is reinforcement, never the sole signal (WCAG 1.4.1).

**The "Nearing budget" chip is NEVER destructive red** — the amber chip family means "caution / attention", and it renders only in the 80–100% band where money is not yet lost. Once spend exceeds the budget the chip disappears and the red negative numerals take over — amber and red never appear on the Remaining row simultaneously (one state, one signal).

AlertPanel severity colors are inherited unchanged: `budget_warning` → warning (amber triangle, `border-l-amber-400`); `budget_overrun` → critical (red octagon, `border-l-red-400`).

Grays: `text-gray-900` primary figures, `text-gray-700` row labels, `text-gray-500` captions and helper text, matching shipped conventions.

### Alert copy templates (backend `impact_text` = FCM push body; locked verbatim, tests assert)

| Alert | Template |
|-------|----------|
| `budget_warning`, scope budget | "{project name} — {trade name} scope has spent {spent} of its {budget} budget ({percent}%)." |
| `budget_warning`, project budget | "{project name} has spent {spent} of its {budget} budget ({percent}%)." |
| `budget_overrun`, scope budget | "{project name} — {trade name} scope has exceeded its {budget} budget — {spent} spent ({percent}%)." |
| `budget_overrun`, project budget | "{project name} has exceeded its {budget} budget — {spent} spent ({percent}%)." |

Formatting rules for alert figures (single-sourced backend helpers, unit-tested):
- **Money:** `$` + thousands separators + cents, with a trailing ".00" stripped — "$8,200", "$10,000", "$8,200.50". This matches the locked CONTEXT example verbatim ("Riverside Remodel — Plumbing scope has spent $8,200 of its $10,000 budget (82%)") while staying deterministic for nonzero cents.
- **Percent:** one decimal, `ROUND_HALF_UP` (the `margin_percent_for` convention), trailing ".0" dropped — "82%", "82.5%", "112%". Pure `Decimal` math, never float (RESEARCH Pitfall 8).
- Every template names the entity, threshold tier (via the sentence shape), spend, and budget figures — the D-04 content contract.

### FCM push (locked)

| Field | `budget_warning` | `budget_overrun` |
|-------|------------------|------------------|
| title | "Budget warning" | "Budget exceeded" |
| body | the `impact_text` string, byte-identical | the `impact_text` string, byte-identical |
| data | `{"type": "budget_alert", "alert_type": "budget_warning"\|"budget_overrun", "alert_id": <uuid str>, "project_id": <uuid str>, "trade_scope_id": <uuid str or "">}` — all values strings (FCM constraint) | same shape |

Tap behavior: **default notification-open** (no in-app routing) — mobile has no alert surface this phase; the payload is shaped for a future alert screen (RESEARCH Open Question 4). Push goes only to `finance.view` holders (D-05) — a UI-invisible contract restated here because keystone test 3 asserts it.

Copy rules honored: no lorem ipsum, no vague labels; helper texts state the consequence, not just the rule; the destructive confirmation names what stops and what is unaffected. Sentence case with terminal periods on captions/helpers/alerts, matching the Phase 32/33 caption convention. Buttons and chip labels carry no terminal period.

## Component & Screen Contract

### 1. Anatomy — budget summary section (both platforms)

Rendered by `CostBreakdownSummary` itself, **between the Total row and the margin section** — budget figures are the cost-side story (they qualify the Total directly above); Revenue/Margin stay the revenue-side conclusion at the bottom. `MarginSummarySection` already opens with its own `Separator`, so ordering composes without edits to it.

Variant rule: **project and trade-scope variants only.** The job variant renders no budget group ever (budgets anchor project/scope — Phase 30 asymmetry; API sends no `budget` block on job breakdowns).

Visual order (web, budget present, warning band shown):

```
Total                                     $8,200.00
──────────────────────────── Separator
Budget                  [Edit]           $10,000.00
Spent                              $8,200.00 · 82%
Remaining      [Nearing budget]           $1,800.00
──────────────────────────── Separator (margin section's own)
Revenue                                       ...
```

- **Budget row:** label "Budget" (`text-sm text-gray-700` / `bodyMedium`) left; right side is `[Edit?] [amount]` with an 8px gap — "Edit" ghost text button (web only, `finance.manage` only, `aria-label="Edit budget"`) then the amount via `formatCurrency` at plain `text-sm` (mobile `_amount` style).
- **Spent row:** label "Spent" left; figure "{amount} · {percent}%" right at plain `text-sm`. **`spent` MUST equal the `grandTotal` rendered in the Total row above — asserted in tests** (RESEARCH Pitfall 6: no drift between alert math and screen math; the backend embeds the same figure). On the trade-scope variant this is the scope's category total — labor exclusion is already honestly declared by the Labor row's "Tracked at job level" note (Phase 32, unchanged); no extra caption.
- **Remaining row:** label "Remaining" left; right side is `[chip?] [figure]` with an 8px gap. Figure at `text-sm font-semibold` (mobile `titleMedium` w700) — the punchline. Chip and color per the state matrix below. Negative values format sign-before-symbol ("-$1,200.00") via the shipped `formatMarginDollars` convention (planner may relocate the helper to a shared module; identical output is the contract).
- **"Set budget" affordance (web only):** when the breakdown has loaded, `budget == null`, and `can("finance.manage")` — render `Separator` + a Budget row whose trailing content is the "Set budget" ghost text button (link-styled, `Button variant="ghost"` sizing, the Phase 32 "Manage rate" recipe). Opens `SetBudgetDialog` in create mode. When `budget == null` and the viewer lacks manage: nothing renders (no separator, no placeholder — byte-identical to today).
- **Mobile:** view-only triad via the shared `BreakdownRow` primitives. No edit affordance, no "Set on web" caption (noise — most entities will have no budget), nothing when `budget` is null/absent.

Data flows through the existing breakdown/rollup responses — the additive `budget` block (`budget_id`, `total`, `spent`, `remaining`, `percent_used`, all Decimal strings) per RESEARCH Surface 1, extended here with `percent_used` so the client never computes a percent. Mobile parses the new key tolerantly (absent = older backend = render nothing), existing keys stay strict.

### 2. State matrix (test-asserted; executor implements exactly these)

| # | State | Condition | Rendering |
|---|-------|-----------|-----------|
| 1 | No budget, no manage (web) / no budget (mobile) | `budget == null` | Budget section renders nothing — no separator, no rows |
| 2 | No budget + manage (web only) | `budget == null` ∧ `can("finance.manage")` ∧ breakdown loaded | Separator + Budget row with "Set budget" ghost button. Never during loading (no flash — see state 7) |
| 3 | Under 80% | `percent_used < 80` | Plain triad; Spent shows "· {percent}%"; no chip, no color |
| 4 | Warning band | `80 ≤ percent_used` ∧ `spent < total` | State 3 + amber "Nearing budget" chip left of the Remaining amount (exact `FinanceFlagChip` recipe) |
| 5 | Exactly at budget | `spent == total` | No chip; Remaining "$0.00" plain; Spent shows "· 100%" — the figure is the signal |
| 6 | Over budget | `remaining < 0` | No chip; Remaining figure (e.g. "-$1,200.00") in destructive/error color, numerals only; Spent percent > 100 renders normally (e.g. "· 112%"). Visually honest: red negative + >100% percent, nothing softened |
| 7 | Loading | Breakdown fetch in flight | Budget section does not render (breakdown rows above already show "—"); it appears when data resolves — never a "—" triad or a premature "Set budget" button |
| 8 | Error (web) / offline (mobile) | Fetch failed | Whole summary already replaced by the inherited error/offline line — no budget-specific treatment |
| 9 | Budget key absent | `budget` key missing in response (older backend) | Section renders nothing; parsers stay tolerant (additive-contract rule) |
| 10 | Job variant | `variant == "job"` | Never renders a budget group, regardless of data |
| 11 | Edit affordance gating | budget exists ∧ web ∧ `can("finance.manage")` | "Edit" button renders on the Budget row; absent for view-only finance users (rows still render — D-13 both-view) |

States 3–6 are mutually exclusive on the Remaining row: at most one of {amber chip, red numerals} ever shows.

### 3. `SetBudgetDialog` (web only)

Reuses `dialog.tsx`, mirrors `RateHistoryDialog` conventions. File: `web/src/features/finance/components/SetBudgetDialog.tsx`. Form reset via an `onOpenChange` wrapper, **NOT** `useEffect` (react-hooks/set-state-in-effect fails `--max-warnings 0` — Phase 32-03 lesson).

**Create mode** (opened by "Set budget"):
1. **Title:** "Set budget — {name}" (20px/600). No subtitle.
2. **Amount field:** label "Budget amount", `Input` with leading `$` affix, `inputMode="decimal"`, autofocused. Helper text beneath (`text-xs text-gray-500`): "You'll get alerts at 80% and 100% of this amount."
3. **Footer:** "Set Budget" primary button, right-aligned; disabled while pending.

**Edit mode** (opened by "Edit"):
1. **Title:** "Edit budget — {name}".
2. **Headline:** eyebrow "CURRENT BUDGET" (`text-xs font-semibold uppercase tracking-wide text-gray-500`) over the figure (`text-2xl font-semibold text-gray-900`, e.g. "$10,000.00"); caption beneath (`text-xs text-gray-500`): "Current spend: $8,200.00 (82%)."
3. **Amount field:** prefilled with the current total. Helper: "Increasing the budget re-arms the 80% and 100% alerts." When the entered value is positive but below current spend, an additional live note appears: "Below current spend — the overrun alert will fire." — informational, never blocks submit (D-10: no floor).
4. **Footer:** "Remove budget" ghost text button in destructive text color, left-aligned; "Save Budget" primary, right-aligned.
5. **Remove confirmation:** clicking "Remove budget" swaps the dialog body to the confirmation copy (Copywriting contract) with "Remove Budget" (destructive `Button` variant) and "Cancel". Cancel returns to the edit form.

**Validation** (client-side, on submit):

| Rule | Message |
|------|---------|
| required, > 0, ≤ 2 decimal places | "Enter a budget greater than $0." |
| ≤ 99,999,999.99 (NUMERIC(10,2) ceiling) | "Enter an amount under $100,000,000." |

**Interaction:** success closes the dialog, fires the success toast, and invalidates the breakdown/rollup query keys so the rows refresh (`useSetBudget`/`useUpdateBudget`/`useDeleteBudget` in `web/src/features/finance/hooks.ts`, invalidation per the `invalidateAllCostEntries` pattern). Errors keep the dialog open with the error toast. Editing below spend does not trigger any special confirmation — the live note already told the truth.

**Accessibility:** focus trapped, initial focus on the amount input, Escape closes (base-ui defaults); the destructive confirm step moves focus to "Cancel" so Enter cannot accidentally destroy.

### 5. Implementation shape (clean-code / SRP)

### 7. Accessibility notes

- Chip and captions are text — meaning never carried by color alone (WCAG 1.4.1); over-budget carries the minus sign and the >100% percent independent of the red numerals.
- The budget section's only interactive elements are the two ghost buttons (web, manage only); both are real `button`s, keyboard-focusable, with visible text labels ("Edit" additionally carries `aria-label="Edit budget"`).
- Reading order matches visual order: Budget → Spent → Remaining, between Total and Revenue.
- Budget figures never appear outside `finance.view`-gated surfaces (inherited mount gating); edit affordances never appear outside `finance.manage` (D-13). Playwright must log in through the UI then SPA-navigate (Phase 32-04: direct `page.goto` leaves `usePermissions` disabled and finance surfaces never render).
