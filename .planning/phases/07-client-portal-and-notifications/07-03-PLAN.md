  <action>
    1. Add Firebase packages to pubspec.yaml:
       - firebase_core: ^4.5.0
       - firebase_messaging: ^16.1.2

    2. Update Android build files for Firebase:
       - mobile/android/build.gradle: add `classpath 'com.google.gms:google-services:4.4.2'` to buildscript dependencies (if not using plugins block)
       - mobile/android/app/build.gradle: add `apply plugin: 'com.google.gms.google-services'` at bottom (or in plugins block)
       - Check the existing build.gradle structure (Gradle plugins DSL vs legacy apply) and use the matching pattern
       - Ensure minSdkVersion >= 21 (Firebase requirement — likely already met)

    3. Add notification channel metadata to AndroidManifest.xml:
       - Inside <application>: `<meta-data android:name="com.google.firebase.messaging.default_notification_channel_id" android:value="job_updates" />`
       - This ensures FCM notifications display on Android 8+ without flutter_local_notifications

    4. Create fcm_service.dart:
       - Top-level background handler (MUST be top-level, NOT a method):
         ```dart
         @pragma('vm:entry-point')
         Future<void> _firebaseMessagingBackgroundHandler(RemoteMessage message) async {
           await Firebase.initializeApp();
           // No navigation — OS shows tray notification
         }
         ```
       - Class FcmService:
         - registerToken(DioClient dioClient) async:
           a. Request notification permission: `await FirebaseMessaging.instance.requestPermission()`
           b. Get token: `final token = await FirebaseMessaging.instance.getToken()`
           c. If token != null, POST to /api/v1/notifications/token with {token, platform}
           d. Listen to onTokenRefresh stream and re-POST on rotation
           e. Null-check token (Pitfall 3 from research)
         - setupMessageHandlers(GoRouter router) async:
           a. FirebaseMessaging.onMessageOpenedApp.listen — extract job_id from data, navigate via router.go(RouteNames.clientJobDetailPath(jobId))
           b. Handle foreground messages: FirebaseMessaging.onMessage.listen — no-op (OS tray shows notification, no in-app UI per CONTEXT.md decision)
         - getInitialRoute() async -> String?:
           a. Call FirebaseMessaging.instance.getInitialMessage()
           b. If message has job_id in data, return RouteNames.clientJobDetailPath(jobId)
           c. Return null otherwise
           d. Called from main() to determine initialLocation for cold-start deep link

    5. Update main.dart:
       - Add `await Firebase.initializeApp()` before runApp
       - Register background handler: `FirebaseMessaging.onBackgroundMessage(_firebaseMessagingBackgroundHandler)`
       - Create FcmService instance and register in GetIt
       - Call FcmService.getInitialRoute() to check for cold-start deep link

    6. Wire token registration into auth flow:
       - In AuthNotifier (or via ref.listen in a suitable provider): when state transitions to AuthAuthenticated, call FcmService.registerToken(dioClient)
       - This ensures token is registered on every login and app launch where user is already authenticated
       - Wrap in try/catch — FCM registration failure must NOT block auth flow
       - On logout: no need to deregister token (backend handles cleanup; deferred complexity)

    7. Wire message handlers:
       - After GoRouter is created in routerProvider (or in main.dart after runApp), call FcmService.setupMessageHandlers(router)
       - This enables deep-link navigation on notification tap
