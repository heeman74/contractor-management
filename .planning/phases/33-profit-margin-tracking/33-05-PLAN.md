Backend wire contract (locked; 33-03 ships it — mock it verbatim in tests):
```json
"margin": {
  "revenue": "20000.00",
  "revenue_basis": "invoiced",
  "margin": "4200.00",
  "margin_percent": "21.0",
  "incomplete": false,
  "incomplete_reasons": []
}
```
Top-level key on `GET /jobs/{id}/cost-breakdown`, `GET /trade-scopes/{id}/cost-breakdown`, and
`GET /projects/{id}/cost-entries`. `revenue`/`margin`/`margin_percent` are nullable strings;
`revenue_basis` ∈ `"invoiced" | "quoted" | "mixed" | "none"`;
`incomplete_reasons` ⊆ `["unrated_labor", "no_cost_data"]`.

Shipped parsing contract (`cost_breakdown.dart`): strict on existing keys
(`categories`, `grand_total` throw `FormatException` when missing), tolerant on new ones —
`LaborCostSummary.tryFromJson` is the template (`is` checks, no bare `as`, null on malformed).
`CostBreakdown.tryFromJson` (used by the project rollup) delegates to `fromJson`, so parsing
`margin` inside `fromJson` covers all three surfaces at once.

Shipped widget internals being extracted (`cost_breakdown_summary.dart`):
```dart
const _unratedChipBackground = Color(0x26F5A623);
```

Verbatim strings (33-UI-SPEC copywriting contract — `find.text` asserts these exactly, identical to web):
- `'Revenue'`, `'Margin'`
- `'Based on approved quote — not yet invoiced.'` (basis `quoted`)
- `'Includes approved quote amounts not yet invoiced.'` (basis `mixed`, project only)
- `'Incomplete cost data'` (chip)
- `'Margin may overstate profit — some costs are missing or unrated.'` (flagged caption)
- `'No revenue recorded — margin will appear once an invoice or approved quote exists.'` (basis `none`)
