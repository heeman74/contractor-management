# Phase 33 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** Phase 33 ships exactly ONE new UI element per platform — a **margin section** appended inside the shipped `CostBreakdownSummary` component (web `web/src/features/finance/components/CostBreakdownSummary.tsx`; mobile `mobile/lib/features/finance/presentation/widgets/cost_breakdown_summary.dart`), rendered on all three existing Costs surfaces (job detail, trade-scope detail, project rollup) on web AND mobile (D-08). No new pages, no new navigation, no new mounts: the margin data arrives on the same breakdown/rollup responses the components already receive (`breakdown.margin`, additive per 33-RESEARCH Pattern 2), so **zero caller/mount-point edits are required** — the section renders internally, beneath the existing Total row.

Everything inherits the "Job Ticket" design system unchanged from the Phase 30/32 contracts. This document pins layout, verbatim copy, and states for the margin section only.

Pre-populated from: 33-CONTEXT.md (D-01..D-14), 33-RESEARCH.md (Patterns 2/3/5/6, state list), 32-UI-SPEC.md (tokens, chip recipe, caption conventions), direct read of both shipped `CostBreakdownSummary` implementations (2026-07-27). User input required: none — all contract questions were answered upstream.

## Color

Zero new hex values. One new sanctioned usage of an existing semantic token (negative margin), one reuse of the Phase 32 accent-chip recipe:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` `#f7f6f2` / `--foreground` `#0e1726` | Page background, body text (inherited) |
| Secondary (30%) | `--secondary`/`--muted` `#ece9e1`, `--card` `#ffffff` | Card surfaces, separators (inherited) |
| Accent (10%) | `--brand` `#f5a623` | Reserved list below — this phase adds exactly one usage: the **incomplete-data chip**, identical recipe to the shipped unrated chip: `bg-brand/15` + `text-amber-900` (`#78350f`); mobile container `Color(0x26F5A623)`, text `Color(0xFF78350F)` |
| Destructive | `--destructive` `#d64545` | Destructive actions (inherited) + **new sanctioned semantic usage: negative margin numerals** (see below) |

Accent reserved for: checked permission toggles, active nav, focus rings, links, primary CTAs, the unrated-hours chip (Phase 32), and — new this phase — the **incomplete-data chip**. Nothing else.

**Negative margin treatment (locked):** when the margin dollar value is negative, the margin figure string (dollars + percent, e.g. "-$350.00 · -8.3%") renders in `text-destructive` on web and `Theme.of(context).colorScheme.error` on mobile — numerals only; the "Margin" label, captions, and chip never change color. This is the standard financial loss convention (red = money lost), semantically distinct from the incomplete flag. The minus sign carries the meaning; color is reinforcement, never the sole signal (WCAG 1.4.1).

**The incomplete-data chip is NEVER destructive red** — it is an informational data-quality nudge, exactly like the Phase 32 unrated chip (32-UI-SPEC precedent, restated in D-05/D-06 discussion). A margin can be simultaneously negative (red figure) and flagged (amber chip); both render, each in its own color.

Grays: `text-gray-900` primary figures, `text-gray-700` row labels, `text-gray-500` captions and the no-revenue note, matching shipped conventions.

## Copywriting Contract

### Standard elements

| Element | Copy |
|---------|------|
| Primary CTA | N/A — the margin section is read-only; no CTA ships this phase |
| Empty state (no costs AND no revenue) | Nothing renders — the existing "No costs recorded yet." empty state below the summary covers it; the margin section stays silent (no duplicate zero-noise) |
| No-revenue note (D-07 — costs exist, no invoice and no approved quote) | "No revenue recorded — margin will appear once an invoice or approved quote exists." |
| Error state (web) | Inherited — the existing "Couldn't load cost breakdown. Refresh to try again." line replaces the whole summary, margin included; no new error copy |
| Error/offline state (mobile) | Inherited — "Breakdown unavailable offline" replaces the whole summary, margin included; no new copy |
| Destructive confirmation | N/A — no destructive action ships this phase |

### Fixed strings (verbatim — tests assert these, web + mobile identical)

| String | Where |
|--------|-------|
| "Revenue" | Revenue row label |
| "Margin" | Margin row label |
| "{formatted dollars} · {percent}%" (e.g. "$4,200.00 · 21%") | Margin figure — dollars via `formatCurrency` (web) / `$` + backend string (mobile); separator is space–middle-dot–space (" · "); percent from backend string with trailing ".0" dropped ("21.0" → "21%", "8.3" → "8.3%"). When `margin_percent` is null with a margin present (zero-revenue-with-invoice edge), dollars render alone — no dot, no percent (D-06: never suppress the number; percent honestly absent) |
| "Based on approved quote — not yet invoiced." | Caption beneath the Revenue row when `revenue_basis == "quoted"` (D-04). Invoiced basis renders NO caption |
| "Includes approved quote amounts not yet invoiced." | Caption beneath the Revenue row when `revenue_basis == "mixed"` (project rollup only — some anchors invoiced, some quoted) |
| "Incomplete cost data" | Chip beside the margin figure when `incomplete == true` (D-05/D-06) — same vocabulary register as the shipped "N hrs unrated" chip; always text, never icon-only |
| "Margin may overstate profit — some costs are missing or unrated." | Caption beneath the Margin row when `incomplete == true` — covers both flag reasons (`no_cost_data`, `unrated_labor`) with one honest sentence; the Labor row's own "N hrs unrated" chip (Phase 32, unchanged) already carries the hour-level detail |
| "No revenue recorded — margin will appear once an invoice or approved quote exists." | Single line replacing the Revenue + Margin rows when `revenue_basis == "none"` (D-07 — neutral note, NOT a flag, NOT the amber chip) |

Copy rules honored: no lorem ipsum, no vague labels; captions state the caveat plus what it means for the number; the no-revenue note names the next step (issue an invoice or approve a quote). Sentence-case with terminal periods on captions, matching the Phase 32 caption convention ("Wage cost only — excludes payroll tax, insurance, overhead.").

## Component & Screen Contract

### 1. Anatomy — margin section (both platforms, all three variants)

Rendered by `CostBreakdownSummary` itself, immediately after the existing Total row. **No mount-point changes**: job detail Costs card, `TradeScopeDetail` Costs section, `ProjectCostsCard` (web); `job_detail_screen.dart`, `trade_scope_detail_screen.dart`, `project_detail_screen.dart` rollup section (mobile) all already pass the breakdown through, and `finance.view` gating is inherited from those mounts (D-10) — nothing new to gate.

Visual order (top → bottom), appended to the existing component:

```
──────────────────────────── Separator (web) / Divider(indent:16, endIndent:16) (mobile)
Revenue                                  $20,000.00
  Based on approved quote — not yet invoiced.        ← caption, quoted basis only
Margin        [Incomplete cost data]   $4,200.00 · 21%
  Margin may overstate profit — some costs are       ← caption, flagged only
  missing or unrated.
```

- **Revenue row:** label "Revenue" (`text-sm text-gray-700` / `bodyMedium`) left; amount right at the platform's standard amount treatment (web plain `text-sm` like category rows; mobile `_amount` — `titleSmall` w600). Basis caption (when quoted/mixed) sits directly beneath at caption style, indented to the row's left padding.
- **Margin row:** label "Margin" left; right side is `[chip?] [figure]` with an 8px gap — chip only when `incomplete == true`, using the exact unrated-chip recipe (rounded-full, `bg-brand/15 px-2 py-0.5 text-xs text-amber-900`; mobile `Color(0x26F5A623)` container, `borderRadius: 999`, `bodySmall` text at `Color(0xFF78350F)`). Figure at Total-row emphasis; destructive/error color when negative. Incomplete caption beneath when flagged.
- **Trade-scope variant:** identical anatomy (scope revenue resolves from scope-anchored invoices/quotes). The scope's Labor row keeps its Phase 32 "Tracked at job level" note — untouched.
- **Project variant:** identical anatomy; `mixed` basis is possible only here; project-level `incomplete` chip/caption identical (D-12: any contributing anchor flagged flags the project).

### 2. State matrix (test-asserted; executor implements exactly these)

| # | State | Condition | Rendering |
|---|-------|-----------|-----------|
| 1 | Invoiced margin | `revenue_basis == "invoiced"`, not flagged | Revenue row + Margin row with figure. NO caption, NO chip (D-04: invoice-backed margin unlabeled) |
| 2 | Quoted margin | `revenue_basis == "quoted"` | State 1 + "Based on approved quote — not yet invoiced." caption under Revenue |
| 3 | Mixed basis (project only) | `revenue_basis == "mixed"` | State 1 + "Includes approved quote amounts not yet invoiced." caption under Revenue |
| 4 | Flagged margin | `incomplete == true` (either reason, any basis) | "Incomplete cost data" chip left of the figure + "Margin may overstate profit — some costs are missing or unrated." caption under Margin. Figure still shown (D-06: partial number + flag, never suppressed) — composes with states 1–3 and 5 |
| 5 | Negative margin | `margin < 0` | Figure (dollars · percent, both signed) in destructive/error color, numerals only. Composes with any basis and with the flag |
| 6 | Percent absent | `margin_percent == null`, `margin != null` (revenue is zero with invoices present) | Dollars only, no " · ", no percent |
| 7 | No revenue | `revenue_basis == "none"` (D-07) | Revenue + Margin rows replaced by the single neutral note (gray caption style). NOT flagged, NOT amber, NOT red |
| 8 | Loading | Breakdown fetch in flight | Margin section does not render (breakdown rows above already show "—" placeholders); it appears when data resolves — never a "—" margin that might vanish |
| 9 | Error (web) / offline (mobile) | Fetch failed | Whole summary already replaced by the inherited error/offline line — no margin-specific treatment |
| 10 | Margin block absent | `margin` key missing/null in response (old backend) | Section renders nothing; component stays tolerant (additive-contract rule, RESEARCH Pitfall 4) |
| 11 | Empty breakdown, no revenue | No categories, zero total, no unrated, basis none | Entire component renders nothing (existing behavior preserved) |
| 12 | **Keystone: empty breakdown WITH revenue** | Zero costs, zero unrated, but `revenue_basis != "none"` (legacy Pitfall-9 job) | The component MUST render: Labor/Total rows at $0.00 plus the margin section in state 4 (flagged, `no_cost_data`). **Contract change: web `isBreakdownEmpty()` must treat a present margin with `revenue_basis != "none"` as non-empty** — today it would return `null` and hide the honesty flag. Mobile renders whenever breakdown is non-null (no change needed) |

### 3. Implementation shape (clean-code / SRP)

- **Web:** new file `web/src/features/finance/components/MarginSummarySection.tsx` exporting `MarginSummarySection` (named to avoid colliding with the `MarginSummary` type in `types.ts`), rendered by `CostBreakdownSummary` after the Total row. Pure display component: props = the margin object (nullable); no fetching, no hooks. Percent formatting via a small exported `formatMarginPercent(percent: string): string` pure function (unit-testable, mirrors `formatUnratedHours`).
- **Mobile:** new file `mobile/lib/features/finance/presentation/widgets/margin_summary_section.dart` with `MarginSummarySection` StatelessWidget, rendered by `CostBreakdownSummary`. Same purity: receives parsed data, never fetches (D-10: nothing persisted to Drift; rides the existing providers).
- **Chip DRY:** the unrated chip and the incomplete chip share one visual recipe. Extract it once per platform (e.g. mobile `FinanceFlagChip` widget; web a shared chip component or single class-string constant) so the two chips cannot drift. Planner's choice of mechanism; identical rendered output is the contract.
- All copy strings are named constants (no magic strings), matching the shipped `_unburdenedCaption` / `UNBURDENED_BODY` pattern.

### 5. Accessibility notes

- Chip and captions are text — meaning never carried by color alone (WCAG 1.4.1); negative margin carries the minus sign independent of the red numerals.
- No new interactive elements: the margin section has zero tap/click targets (no popover — the captions are always-visible static text, the Phase 32 mobile convention applied to both platforms here; nothing to focus, nothing to trap).
- Reading order matches visual order: Revenue before Margin, caption immediately after its row.
- Margin figures never appear outside `finance.view`-gated surfaces (inherited gating; RBAC audit surface unchanged — D-10, Phase 30 D-06 boundary).
