Wire the third-party e-signature provider (Dropbox Sign) behind an adapter, expose send /
embedded-sign-url / webhook / tokenized-public-view / download endpoints, and persist the signed
PDF back into ContractorHub. One embedded request serves both the mobile in-app and emailed
magic-link channels.

Purpose: makes contracts actually signable end-to-end; consumed by web (29-03/29-04) and mobile
(29-05).
Output: `SignatureProvider` + DropboxSign impl, tokenized access, the contracts router, webhook,
notification hooks, and mocked-provider tests.
</objective>

<interfaces>
- Dropbox Sign API: POST /signature_request/create_embedded (returns signature_request_id +
  per-signer signature_id) then GET /embedded/sign_url/{signature_id} (returns a short-lived
  embedded sign URL). Signed file via GET /signature_request/files/{id}?file_type=pdf. Webhook
  posts form field `json` with `event.event_type` + `event.event_hash` (HMAC-SHA256 of
  event_time+event_type using the API key). Text tags in the PDF place fields.
- Secrets: DROPBOX_SIGN_API_KEY, DROPBOX_SIGN_CLIENT_ID (embedded), DROPBOX_SIGN_TEST_MODE — env.
</interfaces>
