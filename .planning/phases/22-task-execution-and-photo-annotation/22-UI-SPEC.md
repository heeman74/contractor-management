## Interaction Contracts

### My Tasks Screen (Mobile — Contractor)

- Single screen accessible from the Projects bottom nav tab (new tab item or nested route)
- Focal point: the task checklist — specifically the checkbox / camera icon as the primary interactive element on each row. The "Mark Done" bottom bar CTA on the Task Detail screen is the terminal action, but on this screen the checkbox drives the main contractor workflow.
- Groups: one collapsible group per trade scope. Scope group header shows scope name + "X/Y" count + percentage text.
- Within each group: tasks ordered by (1) overdue first (due_date < today highlighted with amber background), (2) priority (urgent > high > medium > low), (3) due_date ASC nulls last.
- Across groups: groups ordered by scope `sort_order` from TradeScopes table.
- Collapsible via tap on group header. Collapsed state persists in-session (no persistence to Drift).
- Checkbox behavior: if `photo_required=true` AND no photos attached → tapping shows camera icon instead of checkbox. Tapping camera icon launches ImagePicker. After photo captured and saved to Drift, checkbox becomes available.
- Checkbox toggles: `not_started` / `in_progress` → `complete`. Tap again: `complete` → `in_progress`. Immediate Drift write + sync queue; no await on HTTP.
- Swipe-to-complete: no — checkbox only (avoids accidental swipe completions on construction sites with gloves).

### Task Detail Screen (Mobile — Contractor)

- Navigation: tap task card → `context.push(RouteNames.taskDetail(taskId))` with task data passed as extra.
- Layout: `Scaffold` with AppBar (task title truncated to 1 line), body is single `CustomScrollView` with sections as SliverToBoxAdapters.
- Sections in order: (1) Header (title, status, priority badge, photo_required indicator), (2) Details (description, estimated hours, estimated cost, materials list), (3) Notes, (4) Photos, (5) Attachments.
- Bottom bar: always-visible `BottomAppBar` with "Add Photo" `OutlinedButton` (left) + "Mark Done" `ElevatedButton` (right, primary color). "Mark Done" hidden when task already complete — replaced with "Mark Incomplete" outline button.
- Notes: inline `TextField` with placeholder "Add a progress note..." at the top of the Notes section. Tap "+" `IconButton` or submit keyboard action to add note. New note appended to top of list (newest first). Notes are immutable after save (no edit/delete initially).
- Photos: 3-column `GridView` with fixed cross-axis count = 3 and `childAspectRatio: 1.0`. Thumbnail tap → `PhotoViewerScreen` (full-screen with "Annotate" button). "Add Photo" button at top of section also triggers ImagePicker (camera or gallery).
- Attachments (PDFs): `ListView` of file tiles with PDF icon, filename (truncated 40 chars), file size. Tap → `url_launcher` opens in system PDF viewer. Add via FilePicker.
- Photo count limit enforcement: when count reaches 10, "Add Photo" button shows disabled with tooltip "Maximum 10 photos per task reached."
- PDF count limit enforcement: when count reaches 5, add attachment button disabled.

### Photo Annotation Screen (Mobile)

- Entry: tap "Annotate" button on full-screen photo viewer.
- Layout: `Scaffold` with no AppBar — immersive full-screen. Top-right corner: "Discard Changes" text button + "Save Annotation" text button. Bottom: tool toolbar (horizontal scrollable row).
- Mode toggle: default = view mode (InteractiveViewer handles all gestures — pinch-to-zoom, pan). Tapping a tool icon switches to draw mode (GestureDetector intercepts pointer events; InteractiveViewer `panEnabled: false, scaleEnabled: false`). A floating "Done Drawing" chip at top-center switches back to view mode.
- Tool toolbar: Arrow | Circle | Text | Measure | [color swatches: red, orange, yellow, blue, black] | Undo | (trash = clear all).
- Arrow tool: drag to draw directional arrow with arrowhead. Rendered on pan end.
- Circle tool: drag to draw ellipse from center-to-corner. Rendered on pan end.
- Text tool: tap to place cursor. Show keyboard + `AlertDialog`-style inline text input. On submit: text label placed at tap point.
- Measure tool: drag to draw line. On pan end: show `showDialog` with `TextField` "Enter measurement (e.g. 24 inches)". On submit ("Add Measurement" button): labeled line rendered with tick marks at endpoints. On cancel ("Keep Attachment" does not apply here — measurement dialog cancel simply discards the pending line without any file operation): measurement line discarded.
- Save behavior: `Navigator.pop(context, jsonEncode(annotationLayer))`. Caller (TaskPhotoGrid) receives JSON and writes via `TaskAttachmentDao.updateAnnotation()`.
- Discard behavior: `Navigator.pop(context, null)`. No changes written.
- Orientation: portrait-first. No landscape lock (opposite of DrawingPadScreen which locks landscape).
- Coordinates: all annotation coordinates stored as normalized 0.0–1.0 values relative to original photo dimensions. Denormalized at paint time.

### GC Progress View (Mobile)

- Location: `ProjectDetailScreen` replaces stub `TradeScopeCard` with `TradeProgressCard`.
- Each card shows: colored dot (chart color from rotation), trade name, "X/Y tasks" label, LinearProgressIndicator, contractor name (abbreviated), last activity (relative time: "2h ago", "Yesterday").
- Tap → pushes read-only task list for that scope (reuses `TradeScopeDetailScreen` with a `readOnly: true` flag or separate `GCTaskListScreen`).
- Read-only mode: no checkboxes, no add-photo, no add-note. Tasks show completion status badges. Photo thumbnails (2–3 max) visible on each task row.

### Web Photo Annotation (PhotoAnnotationCanvas)

- Entry: triggered from photo viewer modal (opened from task detail on web admin).
- Layout: fixed-position overlay or full-screen modal. Image centered with canvas overlaid absolutely.
- Mode toggle: toolbar button switches between "Pan" mode (cursor: grab; mouse events for pan/zoom handled by CSS transform) and "Draw" mode (cursor: crosshair; canvas mousedown/mousemove/mouseup capture events).
- Tool toolbar: same 4 tools as mobile (Arrow, Circle, Text, Measure) + color palette (5 colors) + Undo.
- React state: annotations stored in `useRef<Annotation[]>` (not useState). `useEffect([annotations])` redraws full canvas on every annotation change. This prevents React re-renders from clearing canvas state.
- Save: `onSave(JSON.stringify(annotationLayer))` callback propagated to parent. Parent calls PATCH on attachment.
- Discard: close modal without calling onSave. Button label: "Discard Changes".

## Accessibility

- Task checklist cards: `Semantics(label: "{Task title}, {priority} priority, {status}")` wrapping each card
- Checkbox: `Semantics(label: "Mark task complete", checked: task.status == 'complete', button: true)`
- Camera icon (photo gate): `Semantics(label: "Add required photo to complete task", button: true)`
- Photo grid thumbnails: `Semantics(label: "Task photo {N}{annotation_suffix}", image: true)` where annotation_suffix = ", annotated" when annotation_data present
- Annotation tools: `Semantics(label: "{Tool name} annotation tool", button: true, selected: isActive)` for each toolbar item
- Progress bars: `LinearProgressIndicator` with `semanticsLabel: "{X} of {Y} tasks complete"` and `semanticsValue: "{percentage}%"`
- Trade progress cards: `Semantics(label: "{Trade name}: {X} of {Y} tasks complete, last activity {time}")` wrapping card
- All CTAs: minimum 48px touch target on mobile (enforced via `minimumSize: Size.fromHeight(48)` on ElevatedButton / OutlinedButton)
- "Mark Done" button: `Semantics(label: "Mark task complete", button: true)`
- "Add Photo" button: `Semantics(label: "Add photo to task", button: true)`
- Delete confirmation dialogs: `AlertDialog` with explicit title and body copy (not icon-only)
- Color is never the only differentiator: priority levels use both color AND text label on all priority badges
- Web canvas: `<canvas aria-label="Photo annotation canvas" role="img">` with fallback text; annotation toolbar buttons use `aria-label` and `aria-pressed` for active state
