# Phase 32 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** Phase 32 ships three UI surfaces, all extensions of shipped components — no new pages, no new navigation:

1. **Web Team page rates UI** (`web/src/app/(dashboard)/team/page.tsx` + a new `RateHistoryDialog`) — a "Cost Rate" table column and per-member rate-management dialog, rendered ONLY when `can("finance.rates.manage")` (D-09; workers/admin never see the column, matching the zero-exception posture from Phase 30 D-08).
2. **Web `CostBreakdownSummary`** — one shared component mounted inside the three existing Phase 31 Costs surfaces (job detail Costs card, `TradeScopeDetail` Costs section, `ProjectCostsCard`), rendering category totals + labor row + total (D-10).
3. **Mobile `CostBreakdownSummary` widget** (`mobile/lib/features/finance/presentation/widgets/cost_breakdown_summary.dart`) — mounted above the existing `CostListSection` on job/trade-scope detail and in the project rollup section (D-11).

Plus one subtractive change: the "Labor" category is removed from both cost-entry category pickers (`AddCostDialog` web, `add_cost_sheet.dart` mobile) — labor is derived, never manually entered (RESEARCH Pitfall 1).

Everything inherits the "Job Ticket" design system unchanged from Phase 30's contract. This document pins down layout, copy, and states for the three new surfaces only.

Confirmed from `web/src/app/globals.css` ("Job Ticket" identity) — one new sanctioned accent usage, zero new hex values:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` `#f7f6f2` / `--foreground` `#0e1726` | Page background, body text |
| Secondary (30%) | `--secondary` / `--muted` `#ece9e1`, `--card` `#ffffff` | Card surfaces, table container, dialog surface, breakdown row dividers |
| Accent (10%) | `--brand` `#f5a623` (hi-vis amber) | **Reserved list below** — this phase adds exactly one new usage: the unrated-hours badge |
| Destructive | `--destructive` `#d64545` | Not used by new surfaces (rates are append-only — no delete; the existing Phase 31 cost-entry delete hover is unchanged) |

Accent reserved for: checked permission toggles, active nav, focus rings, links, primary CTAs (existing), and — new this phase — the **unrated-hours badge**: `bg-brand/15` wash with `text-amber-900` (`#78350f`) text, communicating "attention: incomplete data" in the brand's hi-vis warning language without introducing a new semantic color. Mobile equivalent: container `Color(0x26F5A623)` (15% alpha brand), text `Color(0xFF78350F)`.

Do NOT use destructive red for unrated hours — unrated is a data-completeness nudge (fix by backdating a rate, D-02), not an error.

Grays on new web content follow the shipped Phase 31 conventions: `text-gray-900` primary, `text-gray-700` secondary, `text-gray-500` meta/empty, `text-gray-400` icon-idle.

| "Breakdown unavailable offline" | Mobile breakdown section when the API fetch fails offline — quiet `bodySmall`, never $0 |
| "Cost Rate" | Team table column header (matches existing uppercase tracking-wide header style) |

## Component & Screen Contract

### 1. Web — Team page "Cost Rate" column

- Rendered ONLY when `can("finance.rates.manage")` returns true; when false the table is byte-identical to today (no placeholder, no disabled column).
- Column position: after "Roles" (last column). Header: "Cost Rate" in the existing `text-xs font-semibold text-gray-500 uppercase tracking-wide` style.
- Cell content: current rate as "$45.00/hr" (`text-sm text-gray-900`), or "—" (`text-gray-400`) when no rate exists; followed by a "Manage rate" text button (`text-sm`, link-styled, existing `Button variant="ghost"` sizing) opening `RateHistoryDialog`.
- Current rates load in ONE batch query (the no-`user_id` mode of `GET /labor-rates/` per RESEARCH Open Question 1) — never per-row requests. While loading: `Skeleton` bar (`h-4 w-16`) per cell, matching the page's existing skeleton pattern.

### 2. Web — `RateHistoryDialog`

Structure (reuses `dialog.tsx`, mirrors `CreateUserDialog` conventions, file under `team/_components/` or the finance feature):

1. **Title:** "Labor rate — {full name}" (20px/600). No subtitle.
2. **Current rate headline:** eyebrow "CURRENT RATE" (`text-xs font-semibold uppercase tracking-wide text-gray-500`) over the figure "$45.00/hr" (`text-2xl font-semibold text-gray-900`) — the exact "Total Spent" pattern from `ProjectCostsCard`. When a future-dated rate exists, a caption below: "Starts {Mon D, YYYY}: $50.00/hr" (`text-xs text-gray-500`). When no rate: figure shows "—" and the empty-state copy (see Copywriting) replaces the history table.
3. **Add-rate form:** two fields side-by-side on ≥sm, stacked on mobile-width — "Hourly rate" (`Input` with leading `$` affix) and "Effective date" (date input, **defaults to today**) — then the "Add Rate" primary button (default `Button` variant, right-aligned). Helper text under the date field per Copywriting contract. Submit disables the button while pending.
4. **History table:** columns "Effective from" / "Rate" / "Added" (added = `created_at` date). Sorted `effective_from` DESC, `created_at` DESC. Row states: future-dated rows carry the "Starts {date}" badge; superseded same-day rows render at `text-gray-400` with a "Superseded" badge (`Badge` with `bg-gray-100 text-gray-700 border-0`, the Team page's existing badge recipe; the "Starts" badge uses the same recipe). All rows remain visible forever — history is the point (success criterion 1).

Interaction: adding a rate optimistically closes nothing — the dialog stays open, the history table and headline refresh (query invalidation), and the success toast fires. This lets Owner/PM immediately verify the entry landed with the right date.

### 3. Web — `CostBreakdownSummary`

Shared component (`web/src/features/finance/components/CostBreakdownSummary.tsx`), props `breakdown` + `variant: "job" | "trade-scope" | "project"`. Mounted:
- Job detail: inside the existing Costs `Card`, **above** `CostEntryList`.
- `TradeScopeDetail`: same position in its Costs section.
- `ProjectCostsCard`: between the "Total Spent" headline and the entry list. When the extended rollup includes `grand_total`, the "Total Spent" figure displays `grand_total` (all-in including rated labor) — the honest number; while loading or when breakdown fields are absent, it falls back to the existing `total` behavior.

Layout: a `space-y-2` list of rows, each `flex items-center justify-between`, `text-sm`. Row order fixed: **Labor, Materials, Subcontractor, Other**, then any custom categories alphabetically. Category rows render only when they have entries (API returns non-zero categories); the **Labor row always renders** on job/project variants — even at $0.00 with unrated hours. A `Separator` then the **Total** row: label "Total" and amount both `font-semibold text-gray-900`.

**Labor row anatomy (job/project variants):**
- Left: "Labor" label + Info icon (`lucide Info`, `h-3.5 w-3.5 text-gray-400 hover:text-gray-600`) as the `PopoverTrigger` (a `button` with `aria-label="About labor cost"` — no `asChild`). `PopoverContent`: `PopoverTitle` "Unburdened labor" + `PopoverDescription` with the verbatim D-06 sentence.
- Right: when `unrated_seconds > 0`, the unrated badge ("{H} hrs unrated", `text-xs rounded-full px-2 py-0.5 bg-brand/15 text-amber-900`) sits immediately left of the amount; then the labor amount (`font-semibold`).

**Trade-scope variant:** the Labor row shows "Tracked at job level" (`text-xs text-gray-500`) in place of an amount — no popover (no figure to qualify), no badge, no $0 (D-08). Total row = category totals only.

**States:** loading → amounts render "—" (existing `ProjectCostsCard` convention); fetch error → the inline error line from the Copywriting contract replaces the summary (entry list below still renders); when `grand_total` is $0 AND `unrated_seconds == 0` AND no categories → render nothing (the existing "No costs recorded yet." empty state below already covers it — no duplicate zero-noise).

### 4. Mobile — `CostBreakdownSummary` widget

`cost_breakdown_summary.dart`, mounted above `CostListSection` in `job_detail_screen.dart` and `trade_scope_detail_screen.dart`, and in `project_detail_screen.dart`'s rollup section. Visibility inherits the callers' existing `financePermissionProvider.canView` gate — no new gating.

- Rows: label (`bodyMedium`) left, amount (`titleSmall` w600) right; 16px horizontal padding matching `CostListSection`; same fixed row order as web. Divider (`indent: 16, endIndent: 16`) before the Total row (`titleMedium` w700 amount — matches `CostEntryCard` emphasis).
- Labor row: unrated chip (same "{H} hrs unrated" string; container `Color(0x26F5A623)`, text `bodySmall` at `Color(0xFF78350F)`, `borderRadius: 999`) left of the amount when unrated seconds > 0. Directly beneath the labor row, the static caption (`bodySmall`, `onSurfaceVariant`): "Wage cost only — excludes payroll tax, insurance, overhead." — always shown when a labor amount is shown (D-06; caption, not tooltip — mobile has no hover).
- Trade-scope variant: labor row's trailing widget is the text "Tracked at job level" (`bodySmall`, `onSurfaceVariant`); no chip, no caption (no figure shown).
- States: loading → amounts "—"; offline/fetch failure → single `bodySmall` `onSurfaceVariant` line "Breakdown unavailable offline" in place of rows (the cached `CostListSection` below still renders); amounts are backend strings end-to-end, never recomputed locally (D-11).

### 5. Category pickers — labor removed

`AddCostDialog` (web) and `add_cost_sheet.dart` (mobile) filter the reserved "Labor" system category out of their category selectors. No replacement copy needed — the option simply does not appear. (Backend 422 guard is the enforcement; the picker filter prevents the user from ever seeing the error.)

### Accessibility notes

- Info popover trigger: `aria-label="About labor cost"`; keyboard-focusable; popover dismisses on Escape (base-ui default).
- Unrated badge is text, not color-only — the hours string carries the meaning (WCAG 1.4.1).
- "Cost Rate" figures never appear outside `finance.rates.manage`-gated UI; breakdown surfaces show derived totals only, never a rate or per-worker figure (RESEARCH Pitfall 7).
- Dialog: focus trapped, initial focus on the rate input, Escape closes (base-ui dialog defaults).
