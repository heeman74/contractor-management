**INT-02 — calendar_day_view.dart (_buildLaneWidgets method):**
After line 227 (closing the `blockedIntervals` list literal), add travel buffer interval generation:

1. Sort this contractor's bookings by `timeRangeStart`.
2. For each consecutive pair, compute the gap: `gap = next.timeRangeStart.difference(current.timeRangeEnd)`.
3. If gap is positive (> 0 minutes) AND gap <= 30 minutes, add a `BlockedInterval(start: current.timeRangeEnd, end: next.timeRangeStart, reason: 'travel_buffer')`.
4. If gap > 30 minutes, clamp: add `BlockedInterval(start: current.timeRangeEnd, end: current.timeRangeEnd.add(Duration(minutes: 30)), reason: 'travel_buffer')`.
5. If gap <= 0 (overlapping/back-to-back), skip — no travel buffer.

CRITICAL: `ContractorLane._buildBookingWidgets()` requires `interval.start.isAtSameMomentAs(booking.timeRangeEnd)` AND `interval.end.isAtSameMomentAs(nextBooking.timeRangeStart)`. For gaps <= 30 min, the interval naturally satisfies both conditions. For gaps > 30 min, the clamped interval will NOT satisfy the `end.isAtSameMomentAs(nextBooking.timeRangeStart)` condition, so the TravelTimeBlock won't render for large gaps — this is acceptable (large gaps aren't travel buffers, they're free time).

Actually, re-reading ContractorLane more carefully: it checks `interval.end.isAtSameMomentAs(nextBooking.timeRangeStart)`. So for the interval to be matched, `end` MUST equal `nextBooking.timeRangeStart`. Therefore: always set `end = next.timeRangeStart` when the gap is reasonable (e.g., <= 60 minutes). For gaps > 60 minutes, skip entirely (those are genuinely free blocks, not travel). This ensures the matching logic in ContractorLane works.

Revised approach:
- For consecutive booking pairs with a gap > 0 and <= 60 minutes: add `BlockedInterval(start: current.timeRangeEnd, end: next.timeRangeStart, reason: 'travel_buffer')`.
- For gaps > 60 minutes or <= 0: skip.
