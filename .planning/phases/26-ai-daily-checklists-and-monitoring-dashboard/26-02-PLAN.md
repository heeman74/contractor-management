4. Create `mobile/lib/features/checklists/data/checklist_dao.dart`:
   - `@DriftAccessor(tables: [DailyChecklists])` class `DailyChecklistDao extends DatabaseAccessor<AppDatabase> with _$DailyChecklistDaoMixin`.
   - `Stream<List<DailyChecklist>> watchTodayForContractor(String contractorId, String dateStr)` — watch query filtering by contractorId and checklistDate == dateStr and deletedAt IS NULL, ordered by createdAt DESC.
   - `Future<void> upsertChecklist(DailyChecklistsCompanion companion)` — insertOnConflictUpdate.
   - `Future<List<DailyChecklist>> getTodayForContractor(String contractorId, String dateStr)` — one-shot query, same filter as watch.

5. Run build_runner again after creating the DAO to generate `checklist_dao.g.dart`.

6. Create `mobile/lib/features/checklists/data/checklist_repository.dart`:
   - `ChecklistRepository` class that wraps DailyChecklistDao and DioClient for API calls.
   - `Future<void> fetchTodayChecklist()` — GET /api/checklists/today, parse response, upsert into Drift.
   - `Stream<List<DailyChecklist>> watchTodayChecklist(String contractorId)` — delegates to DAO with today's date.

7. Create `mobile/lib/features/checklists/presentation/providers/checklist_provider.dart`:
   - `todayChecklistProvider` as `StreamProvider.autoDispose` — watches ChecklistRepository.watchTodayChecklist for current user's contractor ID.
   - On first load, also trigger a fetch from API to refresh data.

8. Create `mobile/lib/core/sync/handlers/checklist_sync_handler.dart`:
   - Follow `billing_milestone_sync_handler.dart` pattern exactly.
   - `entityType = 'daily_checklist'`, `fromJson` parses server response, `toCompanion` creates DailyChecklistsCompanion.

9. Register sync handler in `service_locator.dart` and add entity type to `sync_engine.dart` entity types list. Follow the exact pattern used for billing_milestone_sync_handler registration.
