## Copywriting Contract

### Roles & Permissions matrix — new catalog entries

Group label: **"Finance"**

Position: appended as the **last** group in `PERMISSION_CATALOG` (after the existing `"Portal"` group / `portal.access` entry), so it renders as the final row-group in the matrix table, below "Portal". Rationale: this keeps the new, highly sensitive group visually distinct as an appended section rather than interleaving it near "Quotes"/"Invoices" — per CONTEXT.md D-06, finance.* is explicitly a *new*, separate category from revenue, and burying it next to Quotes/Invoices risks implying equivalence that D-06 explicitly rejects.

Row order within the group (top to bottom), matching D-01/D-02's stated key order:

| Key | Label | Rationale |
|-----|-------|-----------|
| `finance.view` | "View costs, margins & budgets" | Mirrors existing `"View {noun}"` label pattern (`"View invoices"`, `"View clients"`); enumerates what D-01 defines `finance.view` as covering |
| `finance.manage` | "Manage costs & budgets" | Mirrors existing terse `"Manage {noun} & {noun}"` pattern (`"Manage billing & subscription"`, `"Create & manage contracts"`); covers D-01's "create/edit costs and budgets" |
| `finance.rates.manage` | "Manage labor pay rates" | Deliberately separate wording from the other two — no "costs"/"budgets" language — to visually reinforce D-02's requirement that seeing margins must never imply seeing pay rates |

No other copy changes ship this phase. The matrix's existing surrounding copy ("Toggle what each role can do...", "Reset to defaults", "Save changes", the no-permission message) is unchanged and out of scope.

### Team page — explicitly deferred, not built this phase

CONTEXT.md D-07 states labor rates will eventually be managed on the Team page, gated by `finance.rates.manage`. Per 30-RESEARCH.md, Phase 30 ships schema and permission plumbing only — no `CostCategory`/`LaborRate` router, service, or Team-page UI change lands this phase (RESEARCH.md's recommended structure explicitly excludes `repository.py`/`service.py`/`router.py` from Phase 30's `app/features/finance/` module). Therefore:

- No rate field, rate history, or `finance.rates.manage`-gated affordance is added to `web/src/app/(dashboard)/team/page.tsx` in this phase.
- No placeholder, disabled button, or "coming soon" copy should be added either — CLAUDE.md's no-dead-code rule and this phase's schema-only charter both argue against a stub UI with nothing behind it.
- This is a deliberate scope decision, not an oversight: Phase 32 ("Labor Rates and Cost Rollup") owns the actual Team-page rate UI and should treat this UI-SPEC's silence on the Team page as confirmation, not a gap.
