Close the one verification gap in Phase 15: populate client names on calendar booking events.

Purpose: The booking event blocks should display "job title + client name + StatusBadge" per the UI spec, but `clientName` is currently hardcoded to `""` because the Job API response only includes `client_id`, not a resolved name. Output: Calendar booking events display the client's full name when a client is assigned to the job.

   With a helper that builds client_name:
   ```python
   def _job_with_client_name(job: Job) -> JobResponse:
       resp = JobResponse.model_validate(job)
       if job.client is not None:
           parts = [job.client.first_name, job.client.last_name]
           resp.client_name = " ".join(p for p in parts if p) or None
       return resp
   ```
   Then use it in `list_jobs`:
   ```python
   return [_job_with_client_name(j) for j in jobs]
   ```
   Also apply the same helper in `get_job` (line ~172), `search_jobs`, and any other endpoints that return `JobResponse` so the field is consistently populated. IMPORTANT: This is additive-only — no existing fields renamed or removed (per STATE.md decision). Mobile app receives the extra `client_name` field harmlessly (Pydantic ignores unknown fields on the client side; mobile uses Dart models that won't break from extra JSON keys).
