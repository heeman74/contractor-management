## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, chip/badge padding |
| sm | 8px | Compact element spacing, toolbar button gaps |
| md | 16px | Default element spacing, card padding, toolbar row height |
| lg | 24px | Section padding, panel content padding |
| xl | 32px | Layout gaps between toolbar rows |
| 2xl | 48px | Major section breaks, empty state vertical padding |
| 3xl | 64px | Page-level top/bottom spacing |

Exceptions:
- Touch targets on tablet: minimum 44px tall (WCAG 2.5.5 — applies to toolbar buttons and lane header click zones)
- Calendar time axis width: 48px (fixed, not from spacing scale — required by react-big-calendar layout)
- Contractor lane column minimum width: 120px (resizable, default 160px)
- Current time "now" line: 2px thick (below xs — functional element, not layout spacing)

## Interaction Contracts

### Drag-and-Drop Flow

```
User drags booking block
  → Visual: booking block dims to 70% opacity, dashed outline
  → 15-minute snap: block snaps to nearest 15-min slot during drag (step={15})
  → Escape key: snap back to original position, no API call

User releases (drops) booking
  → Optimistic update: booking moves immediately in UI
  → POST /scheduling/conflicts fires
    ├── No conflicts → PATCH /bookings/{id}/reschedule fires
    │     ├── Success → toast.success("Booking moved to {name} at {time}")
    │     └── Error (500/network) → rollback to original position, toast.error({duration: Infinity})
    └── Conflicts found → conflict modal opens
          ├── "Cancel" → rollback to original position, modal closes
          └── "Confirm Anyway" → PATCH /bookings/{id}/reschedule fires (same success/error paths as above)
```

### Click-to-Open Booking Detail

```
User clicks booking event block
  → Sheet slides in from right (w-96)
  → Booking details load from already-fetched TanStack Query cache (no additional API call)
  → "View Full Job →" button navigates to /jobs/[id]
  → Click outside Sheet or press Escape → Sheet closes
```

### Click Empty Slot — Booking Creation

```
User clicks empty time slot in week/day view
  → Booking creation Sheet slides in from right (w-96)
  → Contractor pre-filled from lane (read-only display)
  → Time pre-filled from slot (start time = slot time, end time = start + 1 hour default)
  → Job dropdown: fetches jobs with status "scheduled" or "quote" (no new job creation)
  → "Book Job" → POST /api/v1/scheduling/bookings
    ├── Success → Sheet closes, calendar refreshes (invalidateQueries), success toast
    └── Error → inline error below form, Sheet stays open
```

### View Switching

```
User clicks Week / Day / Month
  → URL updates: /schedule?view=week|day|month (router.replace)
  → Calendar rerenders for new view
  → Week/Day: auto-scroll to current time (scrollToTime={new Date()})
  → Month: day cells with booking counts
```

### Date Navigation

```
← / → arrows: move ±1 week (week view) or ±1 day (day view)
"Today" button: set date to today, scroll to current time
Date picker icon: opens popover date picker
Keyboard Left/Right: same as ← / → buttons (keydown handler on window)
Keyboard "T": jump to today
  → All navigation: URL updates immediately (router.replace), calendar grid shows skeleton (300ms debounce before API call)
```

### Month View Cell Click

```
User clicks day cell in month view
  → URL updates: /schedule?date={clicked-date}&view=day
  → Transitions to day view for that date
```

### Contractor Lane Header Click (Day View Only)

```
User clicks contractor lane header in day view
  → Toggle single-contractor mode for that contractor
  → Header shows: "{contractorName} — {date}" as new panel title
  → Free windows: bg-green-50 zones
  → Blocked intervals: bg-red-50/60 markers
  → Availability loaded from GET /scheduling/availability/{contractorId}
  → Click same header again → return to all-contractors day view
```

### Filter Interactions

```
User clicks trade/status/contractor dropdown
  → Multi-select dropdown opens (shadcn DropdownMenu with checkboxes)
  → Each selection: URL params update immediately (router.replace)
  → Filter chip row updates with removable tags
  → Calendar re-fetches with new filter params (TanStack Query key changes)

User clicks filter chip × button
  → That filter removed from URL params and chip row
  → Calendar re-fetches

"Clear all" link
  → All filter params removed from URL
  → All chips cleared
  → Calendar re-fetches with no filters
```

### Column Resizing (Week/Day View)

```
User hovers right edge of contractor lane header
  → Cursor: col-resize
  → User drags to resize lane width
  → Min width: 120px (enforced)
  → Resize state: stored in local state (not URL, not Redux)
    — resets on page reload (acceptable tradeoff, per Claude's Discretion)
```

### Responsive Behavior

**Tablet (768–1024px):**
- Same layout as desktop
- Touch drag-and-drop enabled
- Horizontal scroll via touch swipe
- Mini sidebar auto-collapses (Phase 13 behavior unchanged)
- Filter toolbar remains accessible (may require horizontal scroll on very narrow tablets)

**Mobile (<768px):**
- Forced single-day view (view switcher hidden)
- One contractor displayed at a time
- Swipe left/right to switch contractors
- No drag-and-drop — calendar is read-only
- Booking event blocks are tappable (opens Sheet detail)
- Click empty slot does NOT open booking creation (mobile = read-only schedule)
- Toolbar simplified: Today + ← / → date navigation + contractor selector

## CSS Scoping Contract

react-big-calendar imports its own global stylesheet. To prevent conflicts with Tailwind 4's `@layer base` resets:

1. Import RBC CSS ONLY inside `schedule-calendar.tsx` (the `"use client"` calendar component):
   ```tsx
   import "react-big-calendar/lib/css/react-big-calendar.css";
   import "react-big-calendar/lib/addons/dragAndDrop/styles.css";
   ```

2. Scope any Tailwind overrides for RBC elements under `.rbc-calendar`:
   ```css
   /* scoped in a <style jsx> block or a separate schedule.module.css */
   .rbc-calendar { /* overrides here */ }
   ```

3. Do NOT add RBC CSS imports to `globals.css` or any layout file.
