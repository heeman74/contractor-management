    Add a synchronous context manager that records every SQL statement executed on
    the shared async engine while the block runs:

    ```python
    @contextlib.contextmanager
    def _count_sql_statements() -> Iterator[list[str]]:
        """Record every SQL statement issued while the block runs.

        The D-03 N+1 guard: a wall-clock ceiling alone cannot prove the company
        rollup is constant in project count, but a statement count can. Listens on
        engine.sync_engine because SQLAlchemy's event API is synchronous by design
        (same reason app/core/tenant.py's after_begin listener is sync).
        """
        statements: list[str] = []

        def _record(conn, cursor, statement, parameters, context, executemany):
            statements.append(statement)

        event.listen(engine.sync_engine, "before_cursor_execute", _record)
        try:
            yield statements
        finally:
            event.remove(engine.sync_engine, "before_cursor_execute", _record)
    ```

    Import `contextlib`, `from collections.abc import Iterator`, `from sqlalchemy
    import event`, `from app.core.database import engine`.

    Add a self-test proving the mechanism works before anything depends on it:
    `test_sql_statement_counter_records_statements` — inside the context manager,
    issue one `GET /api/v1/projects/` as a PM and assert `len(statements) > 0` and
    that at least one recorded statement contains `FROM projects`. Then assert the
    listener is detached afterwards: run the same request outside the block and
    confirm the captured list length did not grow.
  </action>
