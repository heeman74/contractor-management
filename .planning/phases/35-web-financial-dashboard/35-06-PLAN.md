<objective>
Ship `GET /api/v1/projects/{project_id}/financials`: the drill-down's
window-independent aggregate — category mix, derived labor, margin, project
budget and per-trade-scope budget-vs-actual — with no itemized rows.

Purpose: the naive drill-down loops `useTradeScopeCostBreakdown(scopeId)` over a
project's scopes, which is an N+1 across HTTP. Three server-side queries replace
it. Keeping these figures off the trend endpoint means a window change never
restates the headline numbers (D-10).
Output: `ProjectFinancialsResponse`, the service method, the gated route, and
three named tests.
</objective>

**Wire contract (must match plan 35-04's `ProjectFinancials` type):**
```json
GET /api/v1/projects/{project_id}/financials ->
{ "project_id","name","status",
  "breakdown": { "categories":[{"category_id","category_name","total"}],
                 "labor": {"total","rated_seconds","unrated_seconds","basis"}|null,
                 "labor_tracked_at_job_level": false,
                 "grand_total": "40120.00",
                 "margin": MarginSummary, "budget": BudgetVsActual|null },
  "scopes": [ { "trade_scope_id","trade_name","spent","budget": BudgetVsActual|null } ] }
```
`breakdown` is the SHIPPED `CostBreakdownResponse` schema, reused verbatim so the
web's existing `mapCostBreakdown` parses it unchanged. No `entries` key ever
(Pitfall 10). Scopes are ordered by the shipped `TradeScope.sort_order`.

**Shipped pieces to compose:**
```python
# service.py
class FinanceService: async def rollup_for_project(project_id) -> ProjectCostRollup
    # ProjectCostRollup: entries, total, categories, labor: LaborTotals, grand_total,
    #                    margin: MarginSummary, budget: BudgetVsActual | None
    async def trade_scope_spend(trade_scope_id) -> Decimal      # the per-scope definition
# budget_repository.py
async def list_active(self) -> list[Budget]
async def scope_spends(self, trade_scope_ids: list[uuid]) -> dict[uuid, Decimal]
    # already pinned to trade_scope_spend by test_sweep_scope_spends_equivalence_matches_trade_scope_spend
# budget_service.py
def _to_budget_vs_actual(budget: Budget, spent: Decimal) -> BudgetVsActual
# base_service.py
def active_entity_or_404[E](entity: E | None, detail: str) -> E    # treats deleted_at as absent
# schemas.py
class CostBreakdownResponse / class CategoryTotal / class BudgetVsActual
class LaborCostSummary:  total, rated_seconds, unrated_seconds, basis: str = "unburdened"
    # `basis` marks the v4.0 wage-only scope (D-06) and is already on the wire —
    # reuse the schema whole; do not omit or redeclare the field
```

**The D-08 anchor asymmetry the response must stay honest about:** CostEntry
anchors job XOR trade_scope, Budget anchors project XOR trade_scope. Labor is
job-anchored, so a scope's `spent` legitimately excludes labor — the UI shows the
caption `Scope spend excludes labor — labor is tracked at job level.` and the
server must not silently pad the figure.
