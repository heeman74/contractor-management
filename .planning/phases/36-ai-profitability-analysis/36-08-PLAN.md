```python
allowed = collect_allowed_values(candidate.payload)
messages = [{"role": "user", "content": json.dumps(candidate.payload, default=str)}]
for attempt in range(GROUNDING_RETRY_LIMIT + 1):
    response = await call_claude_json_strict(
        PROFITABILITY_SYSTEM_PROMPT, messages, max_tokens=PROFITABILITY_MAX_OUTPUT_TOKENS
    )
    self._log_token_usage(candidate, response)      # defensive getattr reads
    if not response.data.get("confirmed"):
        logger.info("ai_profitability: dismissed project=%s reason=%s", ...)
        return None
    draft = self._to_draft(response.data)
    unmatched = self._ungrounded_literals(draft, allowed)
    if not unmatched:
        return draft
    messages = [*messages,
                {"role": "assistant", "content": response.raw_text},
                {"role": "user", "content": GROUNDING_RETRY_TEMPLATE.format(unmatched=", ".join(unmatched))}]
logger.warning("ai_profitability: dropped ungrounded finding project=%s unmatched=%s", ...)
return None
```

and the publish orchestration:
```python
async def publish_findings(self, company_id: uuid.UUID, target_date: date) -> list[PublishedFinding]:
    """Draft, validate, cap and persist every candidate's finding.

    Per-candidate calls under gather_with_concurrency: the D-10 per-project token
    ceiling stays meaningful, one bad candidate cannot poison the rest, and failures
    return None instead of aborting the batch.
    """
    candidates = await self.scan_candidates(company_id)
    drafts = await gather_with_concurrency(candidates, self._draft_for)
    published = []
    for candidate, draft in zip(candidates, drafts, strict=True):
        if draft is None or not _within_length_contract(draft):
            ...log and continue
        if len(published) >= MAX_FINDINGS_PER_COMPANY_PER_NIGHT:
            ...log the cap drop and continue      # counted AFTER validation
        finding = await self.repository.upsert_finding(FindingUpsert(...))
        published.append(PublishedFinding(...))
    return published
```

**Return the candidate fingerprints alongside the published list.** `publish_findings`
returns `PublishResult(published: list[PublishedFinding], qualifying_fingerprints:
list[str])`, where `qualifying_fingerprints` is `[c.fingerprint for c in candidates]` —
EVERY candidate that still qualifies tonight, including ones whose Claude call raised,
whose draft failed the length contract, or that the nightly cap dropped.

WHY this matters (D-06 correctness): plan 36-09 resolves open findings whose fingerprint
is absent from the keep-set. If the keep-set were built from `published`, a transient
Claude timeout on a still-qualifying condition would resolve its open row; the next
successful night the partial unique index would insert a FRESH row with
`alerted_at IS NULL`, `claim_alert` would succeed, and a SECOND alert would fire for a
condition that never cleared — violating D-06 ("a new alert fires only when the
condition clears and recurs, or worsens into a different band") and reproducing
RESEARCH Pitfall 6. The keep-set must mean "still qualifying", not "successfully
narrated".
