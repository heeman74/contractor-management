```python
"""Grounding validator for AI-authored text (FINAI D-05, SC3).

Every dollar and percent the model writes must already exist in the payload it was
given. That is only tractable if the payload's value set is CLOSED under everything
the prompt permits: callers precompute every citable delta as a named payload field
and the prompt forbids the model from computing anything. Validation is then pure
set membership — small, fast, exhaustively testable, with no false-accept surface.
"""

MONEY_PATTERN = re.compile(r"-?\$\s?\d{1,3}(?:,\d{3})*(?:\.\d{1,2})?|-?\$\s?\d+(?:\.\d{1,2})?")
PERCENT_PATTERN = re.compile(r"-?\d+(?:\.\d+)?\s?%")
CENTS = Decimal("0.01")
PERCENT_PLACES = Decimal("0.1")
WHOLE_DOLLAR = Decimal("1")

@dataclass(frozen=True)
class CitedFigure:
    literal: str        # verbatim, so the retry prompt can name it back
    value: Decimal
    is_percent: bool

@dataclass(frozen=True)
class GroundingResult:
    ok: bool
    unmatched: tuple[str, ...]

def collect_allowed_values(payload: Mapping[str, object]) -> frozenset[Decimal]: ...
def extract_figures(text: str) -> tuple[CitedFigure, ...]: ...
def matches_allowed(figure: CitedFigure, allowed: frozenset[Decimal]) -> bool: ...
def validate_grounding(text: str, allowed: frozenset[Decimal]) -> GroundingResult: ...
```

`collect_allowed_values` recurses through Mappings and non-str Sequences and collects
`Decimal(value)` for every `Decimal` and every non-bool `int`. Strings are skipped
DELIBERATELY: callers pass Decimals as `Decimal` objects and serialize to JSON at the
call site, so a project name can never become a citable number. State that in the
docstring — it is the only reason this stays payload-shape agnostic AND safe.

`extract_figures` runs both patterns, normalizes by stripping `$`, `,`, `%` and
whitespace, preserves a leading `-`, and returns `CitedFigure`s in source order. Keep
the regexes at module level so the function stays one level of abstraction.

`matches_allowed`:
- percent: `any(allowed_value.quantize(PERCENT_PLACES) == figure.value.quantize(PERCENT_PLACES))`
- money: `any(v.quantize(CENTS) == figure.value.quantize(CENTS) or
  v.quantize(WHOLE_DOLLAR, rounding=ROUND_HALF_UP) == figure.value)` — the second
  clause is the whole-dollar tolerance the shipped `format_alert_money` output makes
  unavoidable (`Decimal("10000.00")` renders as `"$10,000"`); test both directions.

`validate_grounding` builds the unmatched tuple from `figure.literal` and returns
`GroundingResult(ok=not unmatched, unmatched=tuple(unmatched))`.

```python
@dataclass(frozen=True)
class ClaudeJsonResponse:
    """A strictly-parsed Claude JSON turn, plus the raw text the retry turn needs."""
    data: dict[str, Any]
    raw_text: str
    input_tokens: int | None
    output_tokens: int | None


async def call_claude_json_strict(
    system_prompt: str,
    messages: Sequence[Mapping[str, str]],
    max_tokens: int = CLAUDE_MAX_TOKENS,
) -> ClaudeJsonResponse:
    """Call Claude and parse the reply as JSON, raising on anything unparseable.

    The strict sibling of call_claude_json. That function returns a caller-supplied
    fallback dict on bad JSON, which is a harmless degradation for a checklist and a
    silent-fabrication path for a grounded finding (SC3). Findings fail closed.

    There is NO transport retry on this path — the exponential-backoff envelope is
    streaming-only (ai/service.py). Callers that want resilience add it deliberately;
    the D-05 grounding retry is a VALIDATION retry and is a different thing entirely.
    """
```

`PROFITABILITY_SYSTEM_PROMPT` must state, as numbered rules:
1. Output schema — "Return ONLY valid JSON matching the schema below — no markdown
   fences, no explanation, no prose before or after":
```json
{
  "confirmed": true,
  "dismissal_reason": null,
  "narrative": "<= 600 chars, one paragraph for the project financials page>",
  "corrective_action": "<= 280 chars: target + direction + one cited payload figure>",
  "alert_summary": "<= 280 chars, the dashboard alert and push body>"
}
```
2. **Figure rules (this is what makes SC3 mechanical):** every dollar figure is
   written with a leading `$`; every percentage with a trailing `%`; numbers are never
   spelled as words. Cite ONLY figures that appear in the payload JSON. Never add,
   subtract, divide, sum, average or round to produce a new number — every figure you
   are allowed to mention is already a named field in the payload.
3. **Corrective action shape (D-09):** name a concrete TARGET drawn from the payload
   (a cost category, a trade-scope budget label, or the quote/rate situation), a
   DIRECTION verb (renegotiate, rebill, reprice, backdate, pause, re-scope), and cite
   ONE payload figure that motivates it. Worked example of the shape:
   "Plumbing scope materials are $3,200 over the approved quote's allowance — rebill
   the change order or renegotiate supplier pricing before drywall starts."
4. **Banned filler**, listed explicitly: "review your costs", "monitor closely",
   "keep an eye on", "consider looking into". An action with no target or no direction
   is a dismissal, not a finding.
5. **Data honesty:** `labor_basis` is "unburdened" — wage cost only, excluding payroll
   tax, insurance and overhead. If labor is material to the claim, say so in the
   narrative. `revenue_basis` "quoted" or "mixed" means part of the revenue is an
   approved quote, not an invoice — do not describe it as billed.
6. **Dismissal contract (D-02):** if the payload does not support a specific,
   figure-backed finding, set `confirmed` to false with a one-sentence
   `dismissal_reason` and leave the three text fields empty strings. A weak finding is
   worse than none.
7. Never mention budget threshold crossings as an alert — budget alerts are a separate,
   already-delivered channel (D-04). Budget figures are context for the action only.
