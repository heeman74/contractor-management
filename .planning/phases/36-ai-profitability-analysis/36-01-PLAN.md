```python
stmt = (
    update(AIProfitabilityFinding)
    .where(AIProfitabilityFinding.id == finding_id, AIProfitabilityFinding.alerted_at.is_(None))
```

`resolve_absent_fingerprints(keep)` runs ONE `UPDATE ... SET resolved_at = now()
WHERE deleted_at IS NULL AND resolved_at IS NULL AND fingerprint NOT IN :keep`
(RLS scopes it to the tenant) and returns `result.rowcount`. When `keep` is empty use
a bare `WHERE deleted_at IS NULL AND resolved_at IS NULL` — `NOT IN ()` is invalid SQL.
This is what makes D-06 band-worsening re-fire: the prior band's row resolves in the
same run, so the new band's fingerprint can insert fresh with `alerted_at IS NULL`.

`latest_open_for_project` selects the newest `created_at DESC` row where
`project_id == project_id AND deleted_at IS NULL AND resolved_at IS NULL`.

No `open_finding_count` method: the D-10 nightly cap counts findings PUBLISHED tonight
(plan 36-08 counts them in-memory), not open rows, and a method with no caller is dead
code (CLAUDE.md).
