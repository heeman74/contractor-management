## Color

## Component Inventory

New components this phase adds or extends:

### 1. Inspection Bottom Bar (TaskDetailScreen extension)

Location: `task_detail_screen.dart` bottom bar — conditional on `task.status == 'complete' && isGcOrAdmin`.

Layout:
- When `showInspectBar == true`: hide "Add Photo" OutlinedButton, replace right button with TWO buttons side-by-side using `Expanded`.
- Left: `OutlinedButton` labeled "Reject" — `foregroundColor: colorScheme.error`, `minimumSize: Size(0, 48)`, always enabled.
- Right: `ElevatedButton` labeled "Approve" — `backgroundColor: colorScheme.primary`, `minimumSize: Size(0, 48)`, disabled (`onPressed: null`) until all checklist items are checked.
- Gap between buttons: `SizedBox(width: 12)` — matches existing bottom bar gap.

Semantics:
- Reject button: `Semantics(label: 'Reject this task — provide rejection reason')`
- Approve button: `Semantics(label: allChecked ? 'Approve this completed task' : 'Complete all checklist items to approve')`

### 2. Inspection Checklist Section (TaskDetailScreen — GC view only)

Shown between "Details" section and "Notes" section when `showInspectBar == true`.

Layout: `SliverToBoxAdapter` > `Padding(EdgeInsets.symmetric(horizontal: 16, vertical: 8))` > `Column`:
- `Divider()`
- `Text('Inspection Checklist', style: textTheme.titleMedium?.copyWith(fontWeight: FontWeight.w600))`
- `SizedBox(height: 8)`
- For each checklist item: `CheckboxListTile` — `contentPadding: EdgeInsets.zero`, `dense: true`, `activeColor: colorScheme.primary`
- Checklist populated from trade scope's `inspectionChecklist` JSON, or universal defaults if null.

Universal default checklist items (exact copy from RESEARCH.md):
1. "Quality of work is acceptable"
2. "Correct materials were used"
3. "Work area is clean and safe"
4. "Safety requirements are met"

### 3. Rejection Bottom Sheet

Triggered by: "Reject" button tap. Uses `showModalBottomSheet` — established pattern from `_addPhoto`.

Layout (Column with `mainAxisSize: MainAxisSize.min`, padding `EdgeInsets.all(16)`, gap 16px between fields):
- `Text('Reject Task', style: textTheme.titleMedium?.copyWith(fontWeight: FontWeight.w600))`
- `SizedBox(height: 8)`
- `DropdownButtonFormField<String>` — label "Reason (required)" — populated with rejection reason list below.
- `SizedBox(height: 16)`
- `TextField` — label "Comment (optional)", maxLines: 3, `textInputAction: TextInputAction.newline`
- `SizedBox(height: 16)`
- `OutlinedButton.icon` — icon `Icons.add_a_photo`, label "Add Photo Evidence" — launches `PhotoAnnotationScreen`, result stored as local path.
- If photo attached: show small `Image.file` thumbnail (64×64, `BoxFit.cover`, `BorderRadius.circular(8)`) with `Icons.close` overlay to remove.
- `SizedBox(height: 24)`
- `SizedBox(width: double.infinity, child: ElevatedButton)` — label "Confirm Rejection" — disabled until rejection reason is selected.

Predefined rejection reasons (exact copy from RESEARCH.md — shown as dropdown options):
1. "Rework needed"
2. "Quality does not meet standard"
3. "Wrong materials used"
4. "Work is incomplete"
5. "Safety concern identified"
6. "Other (see comment)"

### 4. "Rejected" Status Badge

Add `'rejected'` case to `_StatusBadge._color()`:
```
'rejected' => const Color(0xFFB71C1C),
```
Label text: "rejected" (existing `.replaceAll('_', ' ')` handles rendering).

### 5. "Punch" Badge on Task Cards

Add `'punch'` rendering to existing `ProjectStatusBadge` / `_StatusBadge` for punch list items:
- Color: `const Color(0xFFE65100)` (deep orange)
- Label: "Punch"
- Same `Chip` widget with `visualDensity: VisualDensity.compact, padding: EdgeInsets.zero` — matches all other badges.

Position: rendered in the same `Wrap(spacing: 8)` row as status and priority badges on task cards. For punch items, the "Punch" badge replaces the status badge (punch items have their own status tracked separately).

### 6. Flag Capture Flow (Camera-First)

Entry point: "Flag Issue" FAB or button on project detail screen.

Interaction sequence:
1. Tap "Flag Issue" → immediately open camera (D-09). Use `image_picker` `ImageSource.camera`.
2. After photo taken → navigate to `PhotoAnnotationScreen` for annotation.
3. Pop from annotation screen → land on flag form sheet with photo thumbnail shown.
4. "Skip photo" TextButton (shown at launch, before camera opens): label "Skip photo — describe issue instead", navigates directly to flag form sheet without photo.

Flag form fields (in `showModalBottomSheet` or `showDialog`):
- `Text('Flag Issue', style: textTheme.titleMedium?.copyWith(fontWeight: FontWeight.w600))`
- If photo: thumbnail (80×80, `BoxFit.cover`, `BorderRadius.circular(8)`) with remove icon.
- `TextField` — label "Description (required)", maxLines: 3
- `DropdownButtonFormField<String>` — label "Severity" — options: "Low", "Medium" (default), "High"
- `TextField` — label "Location (optional)", e.g. "Northeast corner, 2nd floor"
- `SizedBox(width: double.infinity, child: ElevatedButton)` — label "Submit Flag" — disabled until description is non-empty.

### 7. Site Walk Flags List (Project Detail)

Location: Surface on the project detail screen — either as a new section below TradeProgressCards, or as a badge count on an expandable "Site Walk" section header.

Layout decision (Claude's discretion — use collapsible section):
- `ExpansionTile` with title `Row`: `Icon(Icons.flag_outlined)` + `Text('Site Walk Flags')` + count badge `Chip(label: Text('$count'), ...)` using `Colors.grey.shade600` background.
- Expanded: `ListView` of `ListTile` items, each showing: severity color dot (8×8 `Container` with `BoxDecoration(shape: BoxShape.circle, color: severityColor)`), description (truncated to 1 line), "Convert to Punch" `TextButton` (GC only).
- If no flags: empty state inside the collapsed area (shows when expanded).

### 8. Punch List Items in Trade Scope Task View

Punch items rendered after regular tasks in `TradeScopeDetailScreen`. Separate provider stream (`punchItemsProvider(tradeScopeId)`), concatenated in widget layer.

Card appearance:
- Same `Card` widget as regular tasks (elevation 0, `BorderRadius.circular(12)`, `BorderSide(color: Colors.grey.shade200)`).
- Left edge color bar (4px wide `Container`): `Color(0xFFE65100)` — differentiates visually from task cards at a glance.
- Badges in `Wrap`: "Punch" badge (orange) + priority badge + punch status badge.
- Punch status badge colors:

| Punch Status | Color |
|-------------|-------|
| `open` | `0xFF9E9E9E` (grey) |
| `in_progress` | `0xFF1565C0` (blue) |
| `resolved` | `0xFF388E3C` (green) |
| `verified` | `0xFF1B5E20` (dark green) |

## Interaction States

### Approve Button State Machine

| State | Trigger | Visual |
|-------|---------|--------|
| Disabled | Any checklist item unchecked | `ElevatedButton` with `onPressed: null` — Material 3 auto-dims to `colorScheme.onSurface.withOpacity(0.38)` |
| Enabled | All items checked | `ElevatedButton` with `backgroundColor: colorScheme.primary` |
| Loading | Tapped, awaiting API | Show `CircularProgressIndicator.adaptive()` inside button, disable interaction |
| Success | API returns | Navigate back (pop), show SnackBar "Task approved." |
| Error | API fails | Restore enabled state, show SnackBar error copy |

### Reject Button State Machine

| State | Trigger | Visual |
|-------|---------|--------|
| Always enabled | task is 'complete' && isGcOrAdmin | `OutlinedButton` with `foregroundColor: colorScheme.error` |
| Sheet open | Tapped | `showModalBottomSheet` renders rejection form |
| Confirm disabled | No reason selected | "Confirm Rejection" `ElevatedButton` `onPressed: null` |
| Confirm enabled | Reason selected | "Confirm Rejection" active |
| Loading | Confirm tapped | Sheet shows loading indicator in button, close disabled |
| Success | API returns | Close sheet, navigate back, show SnackBar "Task rejected. Contractor notified." |
| Error | API fails | Restore confirm button, show SnackBar error copy |

### Flag Submit State Machine

| State | Trigger | Visual |
|-------|---------|--------|
| Submit disabled | Description empty | "Submit Flag" `onPressed: null` |
| Submit enabled | Description non-empty | "Submit Flag" active with `colorScheme.primary` |
| Loading | Tapped | Inline loading, form fields disabled |
| Success | API returns | Close form, show SnackBar "Flag recorded." |
| Error | API fails | Restore form, show SnackBar error copy |

## Accessibility

- All bottom bar buttons: `minimumSize: Size(0, 48)` — 48dp touch target minimum.
- All buttons have `Semantics(label: ...)` wrapping — follow existing task_detail_screen pattern.
- Checklist `CheckboxListTile` uses default Flutter accessibility (tappable tile, not just checkbox).
- Rejection reason dropdown: use `DropdownButtonFormField` which provides accessible select semantics.
- Status and priority badges: color is supplemented by label text — not color-only.
- Camera-first flag flow: "Skip photo" link is always reachable as first alternative — no camera-only path.
- Severity in flag form: color dot supplemented by text label in dropdown — not color-only.
