<objective>
Build the mobile offline-first data layer for cost capture: Drift v16 `cost_entries` +
`cost_receipts` tables, DAOs, an outbound `CostEntrySyncHandler` (text CRUD, mirrors
`NoteSyncHandler`), a `CostReceiptUploadService` (binary upload with retry/backoff, mirrors
`AttachmentUploadService` — NOT the broken `TaskAttachment` flow), and an on-demand Dio
repository. Ship DAO + upload-service unit tests in the same change.

Purpose: D-01 mobile = offline field capture. Critical research finding: the
`TaskAttachment` sync flow is silently broken (no registered handler, not in the /sync pull
list) — receipts MUST follow the working `Attachment`/`AttachmentUploadService` pattern.
Pitfall 2: cost data must NOT go into the company-wide `/sync` delta (a non-finance device
would pull it into local Drift) — so inbound reads are ON-DEMAND per anchor, outbound writes
go through the sync-queue drain (which is separate from pullDelta's entity list).

Output: A compiling Drift v16 schema + DAOs + registered push handler + wired upload service
+ on-demand repository, with green DAO and upload-retry unit tests. Screens land in 31-05.
</objective>
