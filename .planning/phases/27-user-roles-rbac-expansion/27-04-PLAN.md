<objective>
Add the editable, per-company permission layer on top of the roles from 27-01. Owner/admin
edit a role→permission-key matrix stored per company (seeded from code-defined defaults,
resettable), and the backend enforces it via a `require_permission` dependency.

Purpose: delivers the "owner and admin can change and update role permissions" requirement.
Consumes 27-01 (the valid role set). Produces the API the web editor (27-02) and the UI-gating
`/me/permissions` endpoint (27-02/27-03) depend on.
Output: permission catalog + defaults, `company_role_permissions` table (migration 0027 +
backfill), an `rbac` feature module (model/repo/schema/service/router), `require_permission`
enforcement wired into the domain gates, seed-on-register, and integration tests.
</objective>
