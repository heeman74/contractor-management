<objective>
Backend foundation for the expanded role system: make owner, project_manager, gc, foreman,
and worker valid, assignable user-level roles; introduce named RBAC capability helpers;
and reconcile the pre-existing gc/owner/foreman/admin-guard inconsistencies.

Purpose: establishes the API + DB contract that the permissions layer (27-04), web (27-02),
and mobile (27-03) plans consume. Nothing outside the backend changes here.
Output: widened role whitelist (pydantic Literal + DB CHECK via migration 0026), four
capability helpers in security.py, reconciled authorization at 3 call sites, updated
provisioning/seed scripts, and updated/added backend tests.

Note: the `require_*` capability helpers added here are the interim enforcement AND the
source of the default permission matrix in 27-04. 27-04 then converts the domain gates
(including the inspection/foreman/roles gates reconciled in Task 3) to DB-backed
`require_permission("<key>")`. The role-based reconciliation in this plan is still correct
and shippable on its own; 27-04 supersedes the enforcement mechanism without undoing it.
</objective>
