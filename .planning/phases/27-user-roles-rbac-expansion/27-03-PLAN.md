<objective>
Mobile (Flutter) support for the expanded role system. The critical fix: `UserRole.fromString`
currently throws `ArgumentError` on any unknown role slug, so a user holding one of the five
new roles would crash the app at login/restore. This plan widens the enum, its parsing, its
labels, and the router guards.

Purpose: consumes the API contract from 27-01 (roles) and optionally 27-04 (`/me/permissions`).
No backend changes. Can run in parallel with 27-02.
Output: eight-value `UserRole` enum with `fromString`/`displayLabel`/capability getters,
router `_checkRoleAccess` updates, a Drift table-comment fix, enum unit tests, and an optional
permissions-consumption task (Task 5) that gates UI on effective permissions.

Tasks 1-4 depend only on 27-01. Task 5 (optional) depends on 27-04's `/me/permissions`.
The server always enforces permissions regardless of mobile UI gating, so Task 5 is purely
UX and can be deferred without a security gap.
</objective>
